# 0003 — 조건은 매물이 아니라 사람에 저장한다

- **상태**: 채택
- **일자**: 2026-08-18
- **관련**: [0001](0001-no-total-score.md), [0002](0002-two-person-premise.md), `docs/02-hypotheses.md` H1·H5

## 한 줄 요약

**"이 집 몇 점"이 아니라 "나는 뭘 원한다"를 저장한다.**

---

## 두 가지 방식

### ① 매물에 저장 — 기존 앱들이 하는 방식

```
매물 A { 통근 32분, 반려동물 가능, 보증금 1억, 내 점수: 4점 }
매물 B { 통근 48분, 반려동물 불가, 보증금 8천, 내 점수: 3점 }
```

집노트가 매물마다 8개 항목을 채점하는 게 이 방식입니다.
**매물 5개면 40번 채점합니다.**

여기서 저장된 건 **점수뿐**입니다.
"나는 통근 40분 이내를 원한다"는 기준은 어디에도 없습니다. 내 머릿속에만 있습니다.

### ② 사람에 저장 — 우리가 할 방식

```
나   { 출근지 강남역, 예산 ≤70만, 통근 ≤40분, 역 도보 ≤10분 }
상대 { 출근지 여의도, 예산 ≤80만, 통근 ≤30분, 방 ≥2개 }

         매물 A ─→ 두 조건에 대입 ─→ 결과
         매물 B ─→ 두 조건에 대입 ─→ 결과
```

기준을 **한 번** 저장하고, 매물은 거기에 넣어보는 값입니다.
**입력은 사람당 몇 번이든 한 번뿐**이고, 매물이 5개든 20개든 늘지 않습니다.

---

## 왜 이렇게 하는가

### 1. 이게 없으면 둘이 쓰는 게 아예 불가능하다 ← 진짜 이유

**기준이 데이터로 저장돼 있지 않으면 상대에게 보낼 수가 없습니다.**

점수만 저장하면 상대에게 "A는 4점, B는 3점"만 보냅니다. 그러면 이렇게 됩니다.

> "왜 4점인데?"

그리고 여기서 대화가 **"그냥 별로야"** 로 끝납니다.

우리가 맨 앞에 적어둔 문제 — *"상대가 뭘 원하는지 한 번도 말한 적이 없다"* —
의 정체가 정확히 이것입니다. **기준이 머릿속에 있어서 공유가 안 되는 것.**

기존 앱들의 공유가 전부 PDF·캡처·카드 전송 같은 단방향에서 멈춘 것도 같은 이유입니다.
**보낼 기준이 저장돼 있지 않으니 결과물만 보낼 수밖에 없습니다.**

### 2. 초대받은 사람의 부담이 10분의 1이 된다

| 방식 | 상대가 해야 하는 일 |
|---|---|
| 매물에 저장 | 매물 5개 × 항목 8개 = **40번 평가** |
| 사람에 저장 | 출근지 · 예산 · 필수 조건 = **4번 입력** |

40번을 요구하면 안 옵니다. 4번이면 옵니다.
**가장 큰 위험(H1)이 이 설계에 직접 걸려 있습니다.**

### 3. 2~3개월을 버틴다

매물은 며칠 만에 사라지는데 집 구하는 데는 두세 달 걸립니다.

- **매물에 저장**: A가 사라지면 A에 넣은 40번이 통째로 증발. 새 매물이 오면 처음부터
- **사람에 저장**: A가 사라져도 조건은 그대로. 새 매물이 오면 **바로 자동 적용**

---

## 전부 사람에 붙이는 건 아니다

| 데이터 | 어디에 | 왜 |
|---|---|---|
| 필수조건, 예산, 출근지 | **사람** | 매물이 바뀌어도 안 변함 |
| 반려동물, 관리비 세부 내역 | **어디에도 아님** | 매물 데이터에 없어 판정 불가 → `확인 필요`로 빼서 중개사 질문 카드로 |
| 통근 시간, 실제 주거비 | **계산 결과** | 사람 조건 × 매물로 뽑아냄 |
| 곰팡이, 수압, 채광, 소음 | **매물** | 그 집 고유 속성이라 사람에 못 붙임 |
| 유지 · 보류 · 제외 | **매물** | 그 매물에 대한 판정 |

**둘 다 있습니다.** 무엇을 어디에 두느냐의 문제입니다.
기존 앱들은 전부 매물 쪽에 몰아넣었고, 그래서 기준이 사라졌습니다.

---

## 결과

- 티켓 2번이 이것을 만드는 작업입니다
- 완료 기준: **매물을 전부 지워도 조건이 남아 있을 것**
- 조건 입력 화면은 온보딩에 몰아넣지 않고 필요한 순간에 하나씩 받습니다
  (출근지는 통근 시간 볼 때, 예산은 비용 볼 때)
- **필수 조건의 개수는 이 결정의 범위가 아닙니다.** 사용자가 0~4개 사이에서 정합니다
  → `docs/11-decision-status.md` §1

## 되돌릴 조건

사용자가 매물별로 세세한 평가를 남기고 싶어 하고,
조건 한 벌로는 매물 간 차이를 표현하지 못한다는 것이 반복 관찰될 때.
그 경우에도 조건은 사람에 두고, 매물별 메모를 **추가**하는 방향으로 간다.
