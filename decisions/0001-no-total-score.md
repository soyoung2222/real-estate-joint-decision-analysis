# 0001 — 종합점수를 내지 않는다

- **상태**: 채택
- **일자**: 2026-08-14
- **관련**: `docs/00-proposal.md`, `decisions/0002-two-person-premise.md`

## 맥락

매물 비교 제품의 자연스러운 귀결은 항목별 점수를 합산해 순위를 내는 것입니다.
실제로 국내 앱이 이미 그렇게 하고 있습니다.

> **집노트** — 8개 항목을 1~5점으로 채점, 중요 항목엔 2배 가중치,
> 안 본 항목은 자동 제외, 0~100 종합점수와 신호등 색으로 표시.

즉 **가중치 기반 채점은 이미 구현되어 있고 무료입니다.**
여기서 차별화하려는 시도는 이미 진 싸움입니다.

## 결정

**매물에 종합점수를 부여하지 않는다. 순위도 매기지 않는다.**

대신 두 사람의 조건을 대조해 세 갈래로 나누고,
가운데 갈래(한쪽만 충족)에 대해 **양보 관계를 문장으로 서술**한다.

```
둘 다 충족    → 후보 유지, 논의 불필요
한쪽만 충족   → 양보 지점, 문장 생성        ← 제품의 존재 이유
둘 다 불충족  → 후보 제외, 자리 비움
```

출력 예시:

> "A를 고르면 통근 왕복 36분과 교통비 월 4만원을 상대가 부담하고,
> 실질 주거비는 월 12만원 싸다."

## 근거

**1. 총점은 양보가 어디서 발생하는지를 가린다.**
"A 82점 / B 76점"은 두 사람의 대화를 "6점 차이네"로 끝냅니다.
정작 필요한 정보 — 누가 무엇을 포기하는가 — 가 합산 과정에서 사라집니다.

**2. 두 사람의 가중치는 애초에 합칠 수 없다.**
한 사람에게 통근이 1순위이고 다른 사람에게 방 개수가 1순위일 때,
이를 하나의 가중 평균으로 만들면 **누구의 것도 아닌 점수**가 나옵니다.
평균은 갈등을 해결하는 게 아니라 은폐합니다.

**3. 대화의 성격이 바뀐다.**
- 총점: "A가 6점 더 높아" → 숫자를 두고 다툼
- 문장: "A면 네가 통근 18분, B면 내가 방 하나" → **교환 조건 협상**

후자만이 합의로 이어집니다.

**4. 이미 있는 것과 정면 경쟁하지 않는다.**
채점·가중치는 집노트가 하고 있습니다. 비어 있는 것은 대조와 서술입니다.

## 결과

- 종합점수 UI를 화면 어디에도 두지 않는다.
- 정렬 기능을 제공하더라도 **단일 축(가격, 통근 시간)**으로만 하고,
  복합 점수로는 정렬하지 않는다.
- 완료 기준: 충돌 뷰의 출력이 **항상 문장 형태**일 것.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 두 사람 점수를 각각 표시 (합산 없이) | 결국 사용자가 눈으로 합산한다. 그리고 점수가 낮은 쪽이 방어적이 된다 |
| 합의도 지표 하나만 제시 | 단일 숫자라는 점에서 총점과 같은 문제 |
| 총점을 내되 충돌 내역을 함께 표시 | 총점이 있으면 사람은 총점만 본다 |

## 되돌릴 조건

사용성 테스트에서 사용자가 **명시적으로 순위를 요구하고**,
문장 서술만으로는 결정에 도달하지 못하는 것이 반복 관찰될 때.
그 경우에도 순위가 아니라 "추천 후보 2개" 형태로 좁혀서 제공한다.

## 되돌릴 조건에 추가 (2026-08-19)

**TwoKeys**(밴쿠버, 2026-05 오픈베타)가 각자 평점 → **총합 평점**으로 일치도를 시각화한다.
가장 가까운 해외 선행 사례가 **우리가 기각한 방식을 그대로 쓰고 있다.**

따라서 되돌릴 조건이 하나 더 생긴다 — **TwoKeys가 유의미하게 성장하면**
총점이 2인 맥락에서도 통한다는 증거가 되므로 이 결정을 재검토한다.
집노트(1인)와 TwoKeys(2인)를 함께 감시한다.
