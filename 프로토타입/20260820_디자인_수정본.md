## 1. 문서 목적

이 문서는 최신 소스에 확정된 정책과 이를 바탕으로 수정한 프로토타입 디자인을 한 번에 확인하기 위한 정리본이다.

기존의 단순한 매물 비교·추천 방식에서 벗어나 다음 질문에 답하도록 정보 구조를 다시 설계했다.

> **“어떤 집이 점수가 높은가?”가 아니라  
> “이 집을 선택하면 누가 무엇을 감수하고, 대신 무엇을 얻는가?”**

따라서 서비스의 역할은 AI가 최종 집을 골라주는 것이 아니라, 두 사람의 조건 차이와 양보 지점을 명확하게 설명하고 **이번에 보러 갈 집 2개를 정하도록 돕는 것**이다.

## 2. 최종 서비스 정의

### 한 문장 정의

함께 살 집을 구하는 두 사람이 각자의 조건을 한 번 저장하고, 최대 5개 관심매물을 조건별로 대조해 **누가 무엇을 양보하는지 확인한 뒤 이번에 방문할 집 2개를 정하는 기능**이다.

### 핵심 범위

| 구분 | 내용 |
| --- | --- |
| 기준 서비스 | 네이버페이 부동산 |
| 진입 구간 | 관심매물 저장 이후 |
| 핵심 사용자 | 함께 살 집을 구하는 2인 |
| 1차 검증 집단 | 예비부부·신혼부부 |
| 2차 검증 집단 | 친구·룸메이트 |
| 비교 후보 | 관심매물 최대 5개 |
| 종료점 | 방문 후보 2개 확정 |
| Hero Feature | 조건 충돌 및 양보 지점 설명 |
| 반복 구조 | 후보 5개 → 방문 2개 → 방문 결과에 따라 2~3회 반복 |

### 하지 않는 것

- 새로운 매물 데이터베이스 구축
- 매물 탐색·지도 서비스 자체 대체
- 종합점수와 복합 순위 제공
- AI의 최종 매물 선택
- 계약·대출·등기 과정 전체 제공

## 3. 핵심 결정과 디자인 반영

| 핵심 결정 | 정책 내용 | 디자인 반영 |
| --- | --- | --- |
| 종합점수를 만들지 않는다 | 여러 조건을 합산한 점수와 순위를 제공하지 않음 | 점수·별점·게이지·순위 행을 모두 제거 |
| 2인을 전제로 한다 | 1인은 기본 시나리오가 아니라 상대 참여 전의 빈 상태 | A는 혼자 먼저 결과를 볼 수 있지만 B의 참여를 기다리는 상태로 표시 |
| 조건은 사람에게 저장한다 | 매물마다 평가하지 않고 각자의 기준을 한 번 저장 | A·B 조건 영역을 분리하고 모든 결과 화면에서 상단에 유지 |
| 판정은 세 갈래로 나눈다 | 둘 다 충족 / 한쪽만 충족 / 둘 다 불충족 | 후보 목록을 세 그룹으로 분리하고 상태별 개수 표시 |
| 확인 필요는 경고가 아니다 | 데이터가 없어서 판정할 수 없는 상태 | 회색·청색 계열의 작은 **? 확인** 배지 사용 |
| 양보 관계를 문장으로 설명한다 | 손실과 이득을 함께 서술 | 상세 화면 상단에 양보 문장을 가장 크게 배치 |
| 양쪽 완화안을 함께 보여준다 | 특정 사람에게만 양보를 요구하지 않음 | A 조건과 B 조건 슬라이더를 동일 비중으로 나란히 배치 |
| 상대 조건은 직접 바꾸지 않는다 | 자기 조건만 수정하고 상대 조건은 제안만 가능 | **내 조건에 적용**과 **완화 제안 보내기** 버튼 분리 |
| 방문 후보는 분할 방식으로 정한다 | 각자 2개 선택 후 겹치면 확정, 안 겹치면 하나씩 선택 | 1라운드·2라운드 구조와 남은 한 자리 비교 화면 제공 |
| 화면에서는 ‘합의’라고 쓰지 않는다 | 사용자에게 부담을 주는 내부 용어 제거 | **이번에 보러 갈 집 정하기**로 통일 |

## 4. 전체 사용자 흐름

### 4.1 초대자 A — PC 웹 우선

정보 밀도가 높고 좌우 비교가 필요하므로 PC 웹을 우선으로 설계했다.

~~~text
관심매물에서 후보 최대 5개 선택
→ 출근지·예산 입력
→ 첫 결과 확인
→ 필수조건 추가
→ 초대 링크 발송
→ 상대 조건 입력 대기
→ 후보별 조건 대조
→ 양보 지점 확인
→ 필요 시 조건 완화 시뮬레이션
→ 각자 방문 후보 2개 선택
→ 방문 후보 2개 확정
→ 중개사 질문 및 방문 준비
~~~

### 4.2 초대받은 사람 B — 모바일 우선

카카오톡·문자 링크에서 진입할 가능성이 높으므로 모바일 화면을 우선으로 설계했다.

~~~text
초대 링크 클릭
→ “이 5개 집을 같이 볼까요?” 후보 미리보기
→ 출근지 입력
→ 예산 입력
→ 실제 통근시간·실부담 첫 결과 확인
→ 필요 시 필수조건 추가
→ 결과 저장 단계에서 로그인
→ A와 함께 조건 대조
~~~

### 4.3 로그인 시점

초대받은 사람에게 진입 직후 로그인을 요구하지 않는다.

~~~text
후보 미리보기
→ 최소 조건 입력
→ 첫 결과 확인
→ 저장·재방문이 필요한 시점에 로그인
~~~

먼저 서비스의 가치를 보여준 뒤 로그인을 요청해 초대 이탈을 줄이는 구조다.

## 5. 화면별 디자인 반영

### 5.1 후보 담기

#### 목적

관심매물 전체를 무제한으로 비교하지 않고, 이번 회차에 실제로 검토할 후보를 최대 5개로 제한한다.

#### 주요 구성

- 기존 검색 필터 표시
- 관심매물 카드
- 후보 선택 체크박스
- **현재 선택 수 / 5** 표시
- 하단 고정 CTA

#### 핵심 문구

> “매물은 최대 5개만 비교해요. 조건은 다음 매물이 들어와도 그대로 남습니다.”

#### 상태

- 관심매물 0개: 먼저 관심매물을 저장하도록 안내
- 관심매물 1~2개: 비교 후보가 적다는 안내 후 진행 허용
- 6개째 선택: 최대 5개 제한 및 교체 안내

---

### 5.2 각자 조건 입력

#### 목적

매물마다 점수를 반복 입력하지 않고, 사람마다 기준을 한 번 저장한다.

#### 기본 입력

1. 출근지
2. 이동수단
3. 가구 총 실부담 상한
4. 필수조건

#### 점진적 공개

~~~text
1단계: 출근지 + 예산
→ 후보별 실제 값 즉시 표시

2단계: 필수조건 ①
→ 충족 여부 판정 시작

3단계: 필요 시 필수조건 ②
→ 결과 추가 정교화
~~~

필수조건 개수와 항목은 아직 최종 확정이 아니며, 현재 프로토타입의 2개는 잠정값이다.

#### 권한 구분

| 조건 | 가능한 행동 |
| --- | --- |
| 내 조건 | 직접 수정 및 적용 |
| 상대 조건 | 수정 제안 발송 |

---

### 5.3 조건 대조 결과

#### 목적

5개 후보를 점수로 정렬하지 않고, 논의 필요성에 따라 세 그룹으로 분류한다.

#### 판정 그룹

| 판정 | 의미 | 화면 처리 |
| --- | --- | --- |
| 둘 다 충족 | 논의할 충돌이 없음 | 초록색 상태와 ✓ 아이콘 |
| 한쪽만 충족 | 한 사람의 양보가 필요함 | 주황색 상태와 ↔ 아이콘 |
| 둘 다 불충족 | 현재 조건에서는 후보 유지가 어려움 | 회색 상태와 — 아이콘 |
| 확인 필요 | 데이터가 없어 자동 판정 불가 | 작은 ? 확인 배지 |

#### 목록 카드 정보

- 매물 식별 정보
- 가구 총 실부담
- 판정 상태
- 누구의 어떤 조건이 얼마나 미달했는지
- 상세 화면 진입

#### 정렬 규칙

- 복합점수로 정렬하지 않음
- **한쪽만 충족** 그룹에서는 미달량이 작은 후보를 먼저 표시
- 정렬 기준을 사용자에게 명시

#### 지도 역할

지도는 판정을 생성하지 않고 **이미 나온 판정 결과를 위치에 표시하는 보조 수단**으로만 사용한다.

- 후보 5개 위치 표시
- 상태 색상 핀
- 실부담 라벨
- 아이소크론·조건 범위 표시 제외

매물 사진과 홍보성 설명은 비교 판단을 편향시킬 수 있어 핵심 비교 화면에서 제외했다.

---

### 5.4 매물 상세 판정

#### 목적

한쪽만 조건을 충족하는 매물을 선택했을 때, 누가 무엇을 감수하고 무엇을 얻는지 정확히 보여준다.

#### 양보 문장 구조

~~~text
[누가 무엇을 얼마나 잃는지]
+ [대신 무엇이 얼마나 나은지]
~~~

#### 적용 예시

> “A는 역까지 3분 더 걷고, 대신 B는 후보 중 가장 짧은 통근과 68㎡ 공간을 얻어요.”

#### 조건 표시 순서

1. 예산
2. 통근시간
3. 각자의 필수조건 ①
4. 각자의 필수조건 ②
5. 선호조건
6. 확인 필요

#### 텍스트 대조 방식

조건마다 단위가 달라 공통 그래프 축을 사용할 수 없으므로 상세 판정은 다음처럼 정확한 값으로 표현한다.

~~~text
역 도보 13분 > 10분  ✕ +3분
통근시간 34분 ≤ 40분  ✓
실부담 128만 ≤ 130만  ✓
~~~

#### 상대 위치 표시

특정 조건에 대해서만 후보 5개 중 상대 위치를 점 플롯으로 표시한다.

~~~text
통근시간  ●   ●   ◉   ●      ●
          22  28  34  45     52분
~~~

여러 조건을 합치지 않기 때문에 종합점수로 오해되지 않는다.

---

### 5.5 조건 완화 시뮬레이션

#### 목적

조건을 바꾸기 전에 어느 정도 완화하면 어떤 후보가 살아나는지 미리 확인한다.

#### 디자인 원칙

- A와 B의 완화안을 항상 동시에 표시
- 임의의 완화폭을 제안하지 않음
- 실제 미달량까지만 시뮬레이션
- 적용 전후 후보 상태 변화를 실시간 표시
- 자기 조건은 적용, 상대 조건은 제안만 가능

#### 예시

| 사용자 | 현재 조건 | 완화안 | 예상 변화 |
| --- | --- | --- | --- |
| A | 역 도보 10분 이내 | 13분 이내 | 둘 다 충족 후보 +2개 |
| B | 전용 66㎡ 이상 | 59㎡ 이상 | 둘 다 충족 후보 +1개 |

#### 후보 이동 표시

~~~text
둘 다 충족      1 → 3
한쪽만 충족     3 → 1
둘 다 불충족    1 → 1
~~~

단일 종합점수가 아니라 각 상태의 개수 변화만 보여준다.

---

### 5.6 후보 0건 및 재탐색

후보가 전부 불충족일 때 무조건 조건 완화를 요구하지 않는다.

#### 분기 기준

~~~text
한 조건만 실제 미달량만큼 풀어서 살아나는 후보가 있음
→ 조건 완화 제안

어떤 조건 하나를 풀어도 후보가 살아나지 않음
→ 재탐색 필터 제안
~~~

두 개 조건을 동시에 낮추는 제안은 하지 않는다.

#### 재탐색 화면

기존 네이버 검색 필터와 두 사람의 조건을 비교해 새로운 필터를 제안한다.

| 현재 필터 | 제안 필터 | 근거 |
| --- | --- | --- |
| 전세 3억 이하 | 유지 | 기존 검색 조건 |
| 아파트 | 유지 | 기존 검색 조건 |
| 면적 설정 없음 | 전용 66㎡ 이상 | B 조건 |
| 역세권 설정 없음 | 도보 10분 이내 | A 조건 |

#### 결과 수 미리보기

> “이 조건으로 약 34개 매물”

필터 적용 전 예상 결과 수를 보여줘 조건이 과도한지 판단할 수 있게 한다.

#### 통근 조건 처리

통근시간은 각자의 출근지가 달라 하나의 네이버 검색 필터로 변환하지 않는다. 대신 새로 담은 매물에 저장된 A·B 출근지 조건을 자동 적용한다.

#### 사용자 선택권

- 이 필터로 찾아보기
- 필터 없이 그냥 찾기
- 내 조건 다시 보기

필터를 자동 적용하지 않고 사용자가 직접 선택하도록 한다.

### 5.7 이번에 보러 갈 집 정하기

#### 목적

무한 협상이나 투표 없이 두 사람의 선택을 최대 2라운드 안에 방문 후보 2개로 정리한다.

#### 확정 방식

~~~text
1라운드: 각자 2개 선택

일치 2개
→ 그대로 방문 후보 확정

일치 1개
→ 일치한 1개는 확정
→ 남은 한 자리를 두 후보의 양보 지점으로 비교
→ 2라운드 재선택

일치 0개
→ 각자 가장 보고 싶은 집을 하나씩 선택
→ 총 2개 확정
~~~

2라운드에서도 선택이 겹치지 않으면 각자의 첫 선택을 하나씩 가져가며 종료한다.

#### 화면 문구

사용자 화면에서는 **합의, 투표, 승패** 표현을 사용하지 않는다.

> “겹치는 게 없네요. 각자 제일 보고 싶은 곳을 하나씩 가시죠.”

#### 남은 한 자리 비교

| A가 고른 후보 | B가 고른 후보 |
| --- | --- |
| A 역 도보 +3분 | A 통근 +5분 |
| B 전용면적 68㎡ 충족 | B 전용면적 −7㎡ |
| A가 3분 더 걷고 B가 공간을 얻음 | A의 통근이 늘고 B가 면적을 감수 |

어느 한쪽을 추천하지 않고 양쪽 대가를 같은 비중으로 보여준다.

### 5.8 방문 후보 확정 및 방문 준비

#### 완료 상태

방문 후보 2개가 정해지면 다음 North Star가 달성된 것으로 본다.

> **초대 발송 후 7일 안에 방문 후보 2개 확정**

두 사람의 선택이 완전히 일치하지 않고 각자 한 개씩 선택한 분할 결과도 완료로 기록한다.

#### 확정 화면 정보

- 방문 후보 2개
- 실부담
- A·B 통근시간
- 선정 방식
- 선택 변경
- 중개 문의

#### 중개사 질문 카드

자동 판정할 수 없는 항목은 방문 전 질문으로 전환한다.

예시:

1. 관리비에 수도·인터넷이 포함되는가?
2. 반려동물 입주가 가능한가?
3. 세대당 차량 등록이 가능한가?

질문은 최대 3개로 제한하며, 이 화면에서는 행동을 유도하기 위해 명확하게 표시한다.

## 7. 시각 디자인 원칙

### 7.1 A·B 구분

A와 B는 색으로 차등하지 않는다.

- 동일한 크기
- 동일한 서체
- 좌우 위치
- A·B 명시 라벨

예외적으로 지도에서 두 통근 경로가 겹치는 경우에만 동일한 굵기와 투명도로 서로 다른 색을 사용할 수 있다.

### 7.2 상태 색상

색상은 사람 구분이 아니라 판정 상태에만 사용한다.

| 상태 | 색상 역할 | 아이콘 |
| --- | --- | --- |
| 충족 | Green / Good | ✓ |
| 미충족 | Orange / Warning | ✕ |
| 확인 필요 | Neutral·Blue / Info | ? |
| 둘 다 불충족 | Muted Gray | — |

미충족은 오류가 아니라 양보 가능한 협상 지점이므로 빨간색 **Critical**로 표현하지 않는다.

### 7.3 금지 시각화

- 레이더·스파이더 차트
- 종합 게이지·도넛 차트
- 별점·하트 개수
- 복합 후보 순위
- 여러 조건을 합친 누적막대
- 통근시간과 비용을 함께 겹친 이중축

여러 조건이 하나의 면적·길이·숫자로 합쳐지면 종합점수와 같은 효과를 만들기 때문이다.

### 7.4 허용 시각화

| 사용 목적 | 시각화 |
| --- | --- |
| 조건별 실제값 비교 | 텍스트 대조 |
| 후보 5개 중 상대 위치 | 점 플롯 |
| 조건 완화 전후 | 슬로프 그래프 |

## 8. 인터랙션 및 상태 규칙

### 조건 변경

- 내 조건은 언제든 수정 가능
- 수정 전 후보 상태 변화 미리보기
- 수정 시 전체 후보 즉시 재판정
- 상대에게 변경 알림

### 상대 조건 변경

- 직접 수정 불가
- 완화 제안만 발송
- 상대가 직접 수락·적용
- 거절 이유는 요구하지 않음

### 매물 소진

- 거래완료·삭제 매물은 즉시 후보에서 제외
- 상대에게 알림
- 확정한 방문 후보가 사라지면 남은 한 자리 선택 화면으로 복귀
- 사람에게 저장된 조건은 그대로 유지

### 선택 변경

- 별도의 무거운 취소 기능을 만들지 않음
- 기존 선택 화면으로 돌아가 다시 선택
- 상대에게 변경 알림만 제공

### 반복 사용

~~~text
1회차: 후보 5개 → 방문 2개 → 둘 다 제외
2회차: 새 후보 추가 → 기존 조건 자동 적용 → 방문 2개
3회차: 필요 시 조건 수정 후 반복
~~~

2회차부터는 조건을 다시 입력하지 않아도 자동 판정된다.

## 14. 최종 요약

이번 디자인 수정의 핵심은 **추천과 채점 중심의 매물 비교를, 두 사람의 기준과 양보 관계 중심의 공동 의사결정으로 전환한 것**이다.

~~~text
기존 방향
매물별 평가 → 점수 합산 → 높은 점수 추천

수정 방향
각자의 조건 저장
→ 매물별 조건 대조
→ 양보 지점 설명
→ 조건 완화 또는 재탐색
→ 각자 선택
→ 방문 후보 2개 확정
~~~

AI는 결정을 대신하지 않는다.  
두 사람이 서로 다른 기준을 이해하고, 어떤 선택의 대가를 감수할지 대화할 수 있도록 **설명·비교·시뮬레이션을 제공하는 역할**을 한다.
