조건 입력 UI 설계 & 임장일기 벤치마크

임장일기·집노트·손품노트를 직접 써본 결과와, 우리 조건 입력 화면(A/B 예시)을 근거로 필수/선택 항목을 정하고 화면을 설계합니다.

A

임장일기 — 실제 사용 화면

온보딩 4문항 → 개인화 요약 → 매물 링크 등록(AI 자동 파싱) → 3단 체크리스트 순서로 확인했습니다.

인트로"매물 하나를, 바로 임장할 수 있게 정리하세요" — 첫 화면부터 가치제안이 명확
Q1/4 · 상황"오늘 어떤 집을 찾고 계신가요?" — 첫집/이사/투자/고객용, 단일 선택
Q2/4 · 페인포인트"임장하고 나면 뭐가 가장 헷갈리나요?" — 우리 문제정의와 동일한 질문
Q3/4 · 필수조건의 원형녹일 점"가장 중요한 것 (최대 3개)" — 입지/가격/상태/구조/투자가치 중 선택. 이게 그대로 체크리스트가 됨
Q4/4 · 탈락조건녹일 점"절대 안 되는 건?" — 우리의 "필수조건 불충족" 개념과 정확히 대응
개인화 요약녹일 점"이사할 집을 찾기 위한 임장이네요. 입지가 중요하지만 자꾸 헷갈리네요" — 답변을 그대로 요약해 되돌려줌
매물 등록"매물 링크를 붙여넣으세요" + "예시 매물로 시작하기"
예시 매물 오류부족한 점"지금은 예시 매물을 불러올 수 없어요" — 데모 기능이 고장난 채 방치. 첫인상 신뢰도 저하
AI 자동 파싱녹일 점"매물 읽는 중 → 핵심 정보 찾는 중 → 방문 카드 준비 중" — 링크만으로 정보 자동 추출, 로딩 자체를 진행 서사로 만듦
3단 체크리스트핵심 참고꼭 확인(필수) · 있으면 좋은 점(선호) · 탈락 조건(dealbreaker) — 우리가 지금 설계하려는 필수/선택 구조와 동일한 3단 분류
지원 사이트한국(네이버부동산·피터팬), 미국(Zillow·Realtor·Redfin), 영국(Rightmove) — 우리는 네이버 안에 있어 불필요하지만 확장성 참고
서비스우리 서비스에 녹여야 할 점부족한 점 / 참고만 할 것
임장일기 ① 온보딩 4문항(상황·페인포인트·중요한 것 최대3개·탈락조건)이 그대로 개인화된 체크리스트로 전환되는 흐름 — 우리 조건입력(필수①②·확인)에 그대로 적용 가능
② 답변을 요약해 "OO한 임장이네요"로 되돌려주는 확인 화면 — 우리 초대 진입 시 "OO님과 함께 고르는 집이네요" 식으로 응용
③ 링크만으로 정보를 자동 파싱하는 로딩 연출(단계별 체크) — 다만 우리는 네이버 내부라 파싱 자체는 불필요 		① 예시 매물 데모가 고장난 채 방치 — 데모/체험 기능은 만들려면 반드시 상시 동작 확인 필요
② 체크리스트가 매물마다 개별 관리 — 매물이 사라지면 그 체크리스트도 함께 사라짐 (우리는 `decisions/0003`대로 조건을 사람에 저장해 이 문제를 피함)
③ 온보딩부터 결제/방문까지 전부 1인 기준 — 상대방(2번째 사용자)을 위한 질문이나 초대 개념 자체가 없음
④ 매물 특징 텍스트가 중개사 원문(광고 문구 포함) 그대로 노출 — 정제되지 않은 정보 품질
집노트 — UI 완성도가 낮고, 항목별 점수를 매겨 사후 평가하는 느낌 — decisions/0001(총점 금지)이 정확히 반대 방향으로 정한 이유가 다시 확인됨. 참고할 요소 없음
손품노트 동선·예산 등 조건을 미리 입력받는 컨셉 자체는 유효 아파트 단지로 범위가 한정됨 — 우리 타깃(원룸·투룸·오피스텔 포함 전월세 전반)에는 그대로 적용하기 어려움
B

조건 입력 필드 — 필수/선택 결정

A/B 예시(출근지·예산·필수①②·선호·확인)를 그대로 스키마로 굳히고, 임장일기의 3단 구조(꼭확인/있으면좋은점/탈락조건)를 겹쳐서 확정합니다.

구분필수 여부개수A 예시B 예시
출근지 · 교통수단항상 필수1강남역 · 대중교통여의도역 · 대중교통
예산 (월 실부담 상한)항상 필수1≤ 130만≤ 150만
필수조건필수 (풀에서 선택)정확히 2통근 ≤40분 · 역 도보 ≤10분전용 ≥66㎡ · 주차 가능
선호조건선택0~1층수 ≥3층(비움)
확인조건선택0~2(비움)반려동물 가능 여부
왜 이 구조가 맞는가 임장일기 Q3("중요한 것 최대 3개")·Q4("절대 안 되는 것")가 그대로 체크리스트의 "꼭 확인"·"탈락 조건"이 되는 걸 보면, 사람마다 무엇이 필수인지가 다르다는 게 핵심입니다. 그래서 반려동물 같은 항목을 처음부터 "확인 전용"으로 고정하면 안 됩니다 — A처럼 필요 없는 사람도 있고, B처럼 필수급인 사람도 있습니다. 항목은 하나의 선택 풀에 두고, 사용자가 자신에게 맞는 자리(필수/선호/확인)에 직접 배치하게 하는 것이 맞습니다.

조건 후보 풀 (사용자가 배치하는 원재료)

거리·공간 — 주로 필수①②에

  • 통근시간 상한
  • 역 도보거리 상한
  • 전용면적 하한
  • 방 개수

편의 — 필수 또는 선호

  • 주차 가능 여부
  • 엘리베이터 유무
  • 화장실 개수·분리형
  • 베란다·발코니 유무

확인 — 예/아니오 사실조회형

  • 반려동물 가능 여부
  • 즉시 입주 가능 여부
  • 근저당(융자) 없는 매물
  • 전입신고 가능 여부

선호 — 있으면 좋음 (최대 1개)

  • 층수(고층 선호 등)
  • 신축 연차
  • 방향·채광

주변환경 — 선호 또는 확인

  • 저층·상가/식당 인접 회피 (벌레 우려)
  • 유흥가·번화가 인접 회피 (소음·치안)
  • 대로변 소음 회피
주변환경 항목을 넣은 이유 벌레가 싫어서 1층·상가 인접 매물을 피하는 사람, 조용한 걸 원해서 유흥가·대로변을 피하는 사람이 실제로 있습니다. 이런 항목은 매물 자체의 속성(면적·주차 등)이 아니라 건물 주변 맥락이라 별도 카테고리로 분리했습니다. 사람에 따라 "선호"에 둘 수도, "필수①②"로 승격할 수도 있게 같은 풀에 둡니다.
확인 항목과 미확인 정보 질문 카드의 연결 "확인" 항목에서 사용자가 "모름 · 중개사에게 물어볼래요"를 고르면, 방문 후보 확정 화면의 미확인 정보 질문 카드에 자동으로 들어가도록 설계하면 입력 부담 없이 정보 공백을 그대로 다음 단계로 넘길 수 있습니다.
C

D

앱 시작화면 — 설명 UI

임장일기의 "가치제안 → 안심 문구" 순서를 가져오되, 우리는 온보딩 질문 없이 2장으로 끝냅니다 — 조건 입력은 이미 STEP C 화면이 따로 있기 때문입니다.

진입 1 · 가치제안
🏠🤝

함께 결정하는 집으로.
둘이서 관심매물 5개를 놓고,

시작하기

임장일기의 "사진은 사진대로, 메모는 메모대로" 톤을 참고했습니다.

진입 2 · 안심 문구

✅ 조건은 나중에, 하나씩만 받아요
✅ 점수가 아니라 "무엇을 양보하는지"를 알려드려요
상대가 아직 없어도 혼자서 실질 주거비·통근은 바로 볼 수 있어요
관심매물 보러 가기

임장일기처럼 온보딩 질문(4단계)을 여기서 하지 않습니다 — 조건 입력은 관심매물 3번째 저장 시점에 자연스럽게 유도합니다 (킥오프카드 STEP 1 참고).

E

웨딩노트 — 초대 수락 화면, 그리고 발견한 결함

웨딩노트는 브리프 v0.1에서 이미 "2인 초대가 실제로 작동한다"는 존재 증명으로 인용됐던 서비스입니다. 이번에 초대 수락자 화면까지 직접 확인한 결과, 우리 H1 설계에 그대로 반영해야 할 결함을 하나 발견했습니다.

초대 수락"○○○님의 결혼 준비에 함께하시겠어요?" — "함께하기" 버튼 하나로 즉시 합류. 가입 절차 없이 매끄러움
알림 번호 입력수락 직후 "알림 받을 번호를 남겨 주세요" — 카카오톡 알림톡 수신 동의가 선택 단계로 분리되어 있음. "나중에 하기"로 건너뛸 수 있음
합류 후 홈"○○○님 안녕하세요! 결혼 준비를 시작해요" — 수락자 본인에게는 확인 화면이 바로 주어짐
알림 안내 배너"알림은 번호를 남긴 사람에게만 가요" — 번호를 남기지 않으면 그 사람은 이후 어떤 알림도 받지 않는다는 것을 명시
홈 하단웨딩박람회 광고 노출 — 알림·초대 흐름과는 무관하지만 홈 화면 구성 참고용
발견한 문제내용
초대 수락 알림이 양쪽 모두에게 안 감 상대가 "함께하기"를 눌러 실제로 합류해도, 초대를 보낸 사람은 물론 수락한 사람 본인의 앱에도 "함께 시작됐다"는 알림이 뜨지 않는다. 직접 확인해봐도 양쪽 다 아무 알림을 못 받았다 — 즉 초대자만의 문제가 아니라, 이 서비스에는 이벤트 발생 시 알림을 쏘는 장치 자체가 없다. 알림은 오직 "번호를 남긴 사람"에게 가는 카카오톡 알림톡(결제일·예식일 등 일정 안내)뿐이고, 그마저도 초대·합류라는 이벤트와는 무관하다.
우리 서비스에 반드시 반영 — 양방향 알림을 기본 원칙으로 H1(초대 수락률)이 최우선 지표인데, 웨딩노트는 애초에 "이벤트가 생기면 알린다"는 장치 자체가 없어서 초대자·수락자 둘 다 아무것도 모른 채로 있게 됩니다. 이건 초대 수락 하나의 문제가 아니라 공동 작업 서비스의 기본 조건입니다 — 혼자 쓰는 앱이 아니라면, 상대가 뭔가 하면 나에게 보이고 내가 뭔가 하면 상대에게 보여야 합니다.

그래서 "수락" 뿐 아니라 상태가 바뀌는 모든 지점에서, 관련된 두 사람 모두에게 알림을 보냅니다. 전화번호 같은 별도 옵트인 단계도 두지 않습니다 — 이미 로그인된 계정에 앱 알림으로 기본 켜두고, 원치 않으면 설정에서만 끄게 합니다.
  • 상대가 초대를 수락함 → 나에게 알림
  • 상대가 조건 입력을 완료함 → 나에게 알림
  • 내가(또는 상대가) 새 매물을 공동 후보에 추가함 → 상대에게 알림
  • 매물 평가·양보 지점이 갱신됨 → 양쪽 모두에게 알림
  • 방문 후보가 확정되거나 유지·보류·제외로 바뀜 → 양쪽 모두에게 알림
