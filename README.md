# real-estate-joint-decision-analysis

둘이 같이 집 고를 때 쓰는 기능. 네이버페이 부동산 역기획.

> **둘이서 관심매물 5개를 놓고, 이번에 보러 갈 2개를 정한다.**

아직 안 만들었습니다. 지금 이 저장소에는 조사 결과와 판단 기록만 있습니다.
네이버와 무관한 개인 작업입니다.

---

## 무슨 문제인가

집을 저장한 다음부터는 전부 앱 밖에서 일어납니다.

```
찜하기 → 카톡으로 링크 보내고 → 지도로 출퇴근 재보고
       → 대출 계산기 켜고 → 중개사한테 전화하고 → 메모장에 적고
```

그리고 이 결과는 앱으로 **안 돌아옵니다.** 남는 건 오래된 찜 목록뿐입니다.

둘이 구하면 문제가 하나 더 있습니다.
**상대가 뭘 원하는지 한 번도 말한 적이 없습니다.** 그래서 대화가 이렇게 끝납니다.

> "그 집 어때?"
> "음… 그냥 별로야"

## 뭘 만드나

둘의 조건을 각각 받아서, 매물마다 셋 중 하나로 답합니다.

| 결과 | 처리 |
|---|---|
| 둘 다 OK | 얘기할 게 없음 |
| **한 명만 OK** | **누가 뭘 포기하는지 문장으로 보여줌** |
| 둘 다 NO | 후보에서 뺌 |

**가운데 한 줄이 전부입니다.** 점수가 아니라 이런 문장이 나옵니다.

> "A로 가면 네 출퇴근이 왕복 36분 늘고 교통비가 월 4만원 더 든다.
> 대신 집값은 월 12만원 싸다."

## 안 하는 것

- **어느 집이 정답인지 안 정해줍니다.** 고르는 건 두 사람이 합니다
- **총점 안 냅니다.** 점수로 합치면 누가 뭘 포기하는지가 가려집니다 → [0001](decisions/0001-no-total-score.md)
- **혼자 쓰는 앱으로 안 만듭니다** → [0002](decisions/0002-two-person-premise.md)
- **매물 DB를 새로 안 만듭니다.** 이미 있는 찜 목록 위에 얹습니다

## 핵심 설계 한 가지

**"이 집 몇 점"이 아니라 "나는 뭘 원한다"를 저장합니다.**

기존 앱들은 매물마다 점수를 매깁니다. 매물 5개면 40번 채점하고,
그 매물이 나가면 40번이 전부 날아갑니다.
게다가 상대에게 보낼 수 있는 게 점수뿐이라 "왜 4점인데?"에 답을 못 합니다.

우리는 사람마다 조건을 **한 번** 받습니다.

```
나   :  출근지 강남역 · 예산 70만 · 통근 40분 이내 · 역 도보 10분 이내
상대 :  출근지 여의도 · 예산 80만 · 통근 30분 이내 · 방 2개 이상
```

- 입력은 사람당 4번. 매물이 5개든 20개든 안 늘어납니다
- 매물이 사라져도 조건은 남아서 새 매물에 자동으로 적용됩니다
- **무엇보다, 상대에게 보낼 게 생깁니다**

*(반려동물처럼 매물 데이터에 없는 항목은 조건으로 받지 않고 `확인 필요`로 빼서
중개사에게 물어볼 목록으로 넘깁니다. 없는 걸 "안 됨"으로 판정하면 후보가 잘못 탈락합니다.)*

→ [0003](decisions/0003-conditions-belong-to-people.md)

## 가장 큰 위험

**상대가 초대를 안 받으면 이 기능은 없는 거나 마찬가지입니다.**

혼자 쓰면 이건 이미 국내에 스무 개 넘게 있는 임장 기록 앱 중 하나가 됩니다.
그래서 **다른 걸 만들기 전에 이것부터 잽니다.**

## 범위

| | | 왜 이 숫자인가 |
|---|---|---|
| 몇 명 | 2명 | |
| 매물 | 최대 5개 | 실제로 사람들이 4곳 정도 보고 계약합니다 |
| 결과물 | 보러 갈 2곳 | |
| 얼마나 걸리나 | 한 번 정하는 데 며칠, 집 구하는 전체는 2~3개월 | 전세는 평균 2.5개월, 30대는 2.7개월 |

매물은 계속 바뀌고 조건은 그대로 남습니다.
그래서 조건을 사람 쪽에 저장하는 게 중요합니다.

*(출처: 당근부동산 2026년 5월 조사, 거래 완료한 971명)*

## 확인해야 할 것

| | 지금 상태 |
|---|---|
| **상대가 초대를 받아서 조건을 입력하나** | **모름 — 제일 먼저 확인** |
| 집 구할 때 여러 번 비교하나 | ✅ 맞음 (2.5개월간 4.1곳) |
| 둘이 고를 때 조건이 실제로 충돌하나 | ✅ 맞음 (미국인 77%가 파트너와 다툼, 상위 3개가 조건) |
| **그 충돌 때문에 더 오래 걸리나** | **모름 — 이게 이 제안의 핵심인데 비어 있음** |
| 출근지·예산을 입력해줄까 | 한 번에 안 묻고 필요할 때 하나씩 받으면 됨 |
| 네이버 데이터로 비용 계산이 되나 | 반만 됨. 그래서 계산에 쓴 가정을 화면에 다 밝힘 |

자세한 건 [`docs/02-hypotheses.md`](docs/02-hypotheses.md).

## 만드는 순서

**1번이 안 되면 나머지는 만들 이유가 없습니다.**

1. **초대를 받는지 먼저 재기** — 복잡한 계산 없이 목록 공유 + O/X만
2. 조건을 사람에 저장하는 구조 만들기
3. 실제 주거비 계산기 (가정 공개 포함)
4. 충돌 화면 (누가 뭘 포기하는지)
5. 물어볼 것 정리 + 보러 갈 2곳 확정
