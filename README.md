# real-estate-joint-decision-analysis

부동산 공동 의사결정 분석 — 네이버페이 부동산 역기획

**함께 집을 구하는 두 사람이 최대 5개 관심매물의 필수조건·통근·실질 주거비·미확인 정보를
비교하고, 방문 후보 2개를 정한다.**

> **상태 — 가설 검증 전.** 아직 아무것도 구현하지 않았습니다.
> 이 저장소는 현재 분석과 결정 기록이며, 코드는 H1이 통과한 뒤에 들어옵니다.

네이버페이 부동산 내 기능으로 상정한 역기획입니다.
네이버와 무관한 개인 작업이며, 공식 로드맵이나 실제 논의와는 관계가 없습니다.

---

## 왜

사용자가 관심매물을 저장한 뒤에 하는 일은 대부분 서비스 밖에서 벌어집니다.

```
관심매물 저장
  → 카카오톡으로 공유
  → 지도에서 출퇴근 시간 확인
  → 대출 계산기
  → 중개사에게 문의
  → 방문 일정 조율
  → 메모장에 장단점 기록
  → 계약 위험 별도 검색
```

그리고 그 결과는 서비스로 돌아오지 않습니다. 남는 것은 오래된 관심매물 목록뿐입니다.

둘이 함께 구할 때는 여기에 하나가 더 얹힙니다. **상대의 조건이 한 번도 명시된 적이 없어서**
대화가 "그냥 별로야"로 끝나고, 비교는 매번 처음부터 다시 시작됩니다.

## 무엇을 만드는가

두 사람의 조건을 각각 받아, 매물마다 세 갈래로 나눕니다.

| 결과 | 처리 |
|---|---|
| 둘 다 충족 | 후보 유지 — 논의할 것이 없다 |
| **한쪽만 충족** | **양보 지점 — 누가 무엇을 주고받는지 문장으로 서술** |
| 둘 다 불충족 | 후보에서 제외 — 자리를 비운다 |

가운데 갈래 하나가 이 제품이 존재하는 이유입니다. 출력은 점수가 아니라 문장입니다.

> "A를 고르면 통근 왕복 36분과 교통비 월 4만원을 상대가 부담하고,
> 실질 주거비는 월 12만원 싸다."

## 무엇을 만들지 않는가

- **어느 집이 정답인지 결정해주지 않습니다.** 결정은 두 사람이 합니다.
- **종합점수로 순위를 매기지 않습니다.** 총점은 양보가 어디서 발생하는지를 가립니다.
  → [`decisions/0001-no-total-score.md`](decisions/0001-no-total-score.md)
- **1인용으로 만들지 않습니다.** 2인이 전제입니다.
  → [`decisions/0002-two-person-premise.md`](decisions/0002-two-person-premise.md)
- **새 매물 데이터베이스를 만들지 않습니다.** 이미 있는 관심매물 위에 얹습니다.
- **장기 비교 보드가 아닙니다.** 이번 주 방문 결정까지가 수명입니다.

## 범위

| 항목 | 값 |
|---|---|
| 참여자 | 2인 |
| 후보 매물 | 최대 5개 (6개째는 하나를 빼야 추가) |
| 산출물 | 방문 후보 2개 + 방문 순서 |
| 수명 | 며칠 — 매물 회전보다 짧게 |

제한이 곧 기능입니다. 매물이 며칠 만에 사라지는 환경에서
비교표를 오래 유지하려는 설계는 반드시 무효화됩니다.

## 검증할 가설

| # | 가설 | 상태 | 판정 기준 |
|---|---|---|---|
| **H1** | **초대받은 상대가 실제로 들어와 조건을 입력한다** | **미검증 · 최우선** | 초대 수락률 — 임계값 `측정 필요` |
| H2 | 2인 집찾기에서 갈등·반복 비교가 충분히 큰 문제다 | 미검증 | 인터뷰에서 "의견이 갈려 결정이 지연된 경험"이 과반 |
| H3 | 사용자가 출근지·예산·대출조건을 입력할 의향이 있다 | 설계로 완화 | 조건 입력 시작 대비 완료율 |
| H4 | 보유 매물 데이터로 의미 있는 비용 비교가 가능하다 | 부분적 불가 | 전제 문구 노출 후 신뢰도가 오르는지 |
| H5 | 매물 회전이 비교 주기보다 느리다 | 설계로 완화 | 후보 등록→방문 확정 중앙값 < 평균 게시 기간 |

**H1이 거짓이면 나머지가 모두 참이어도 제품이 성립하지 않습니다.**
상대가 들어오지 않으면 이것은 국내에 이미 스무 개 넘게 있는 1인용 임장 기록 앱이 됩니다.
따라서 조건 대조 로직을 만들기 전에 H1부터 측정합니다.

세부 판정 기준은 [`docs/01-hypotheses.md`](docs/01-hypotheses.md).

## 조사 요약 (2026.08)

국내 앱스토어와 디스콰이엇 공개 정보를 직접 확인한 결과입니다.
**부품은 전부 있는데 두 사람을 잇는 배선만 없습니다.**

| 이미 있는 것 | 대표 사례 |
|---|---|
| 항목별 채점·가중치 | 집노트 — 8개 항목 5점 척도, 중요 항목 2배 가중치 |
| 매물 나란히 비교 | 임장노트 — 가격·평점·체크리스트 병렬, PDF 리포트 |
| 총 주거비 계산 | 핀다, 당근부동산, EZB 부동산계산기, 한국부동산원, 바로계산 |
| 두 사람 조건 매칭 | cozymate, 한집친구 — 생활패턴·예산 기반 룸메이트 매칭 |

비어 있는 것은 **두 사람의 조건을 각각 받는 자리** 하나입니다.
확인한 임장·매물기록 앱 20개 이상이 모두 1인용이었고,
공유 기능의 실체는 PDF 내보내기·화면 캡처·카드 전송 같은 단방향이었습니다.

원본: [`docs/02-research-2026-08.md`](docs/02-research-2026-08.md)

## 실행 순서

순서를 뒤집으면 안 됩니다. **1번이 실패하면 2번 이후는 만들 이유가 없습니다.**

1. **초대 수락률 측정** — 조건 대조 없이, 목록 공유 + O/X만
2. **조건 모델 정의** — 조건의 저장 주체를 매물이 아닌 사용자로 귀속
3. **실질 주거비 환산기** — 6개 항목 + 전제 공개
4. **충돌 뷰** — 세 갈래 분기와 양보 문장 생성
5. **질문 카드 · 방문 후보 확정** — 유지·보류·제외 순환
