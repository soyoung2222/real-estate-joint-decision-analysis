# 뭐가 사실이어야 이게 성립하나

*최종 갱신 2026-08-20*

**"몇 점 이상이면 통과"를 먼저 정해놓고 잽니다.**
안 그러면 결과를 보고 나서 기준을 만들게 됩니다.

숫자가 비어 있는 건 지금 비교할 기준값이 없어서입니다. 지어내지 않았습니다.

## 한눈에

| | 확인해야 할 것 | 지금 상태 |
|---|---|---|
| **H1** | **상대가 초대를 받아서 조건을 입력하나** | **모름 — 제일 먼저** |
| H2-a | 집 구할 때 여러 번 비교하나 | ✅ 맞음 |
| **H2-b-1** | **둘이 집 고를 때 조건 충돌이 실재하나** | ✅ **확정** |
| **H2-b-2** | **그 충돌이 결정을 지연시키나** | **모름 — 핵심인데 비어 있음** |
| H3 | 출근지·예산을 입력해줄까 | 설계로 줄일 수 있음 |
| H4 | 네이버 데이터로 비용 계산이 되나 | 반만 됨 |
| H5 | 매물이 비교보다 빨리 사라지나 | 반은 맞고 반은 틀림 |

**H1과 H2-b-2 둘이 이 제안의 급소입니다.** 나머지는 방법이 있습니다.

## H1 — 초대받은 상대가 실제로 들어와 조건을 입력한다

**상태: 미검증 · 최우선**

이것이 거짓이면 나머지가 모두 참이어도 제품이 성립하지 않습니다.
상대가 들어오지 않으면 이 제품은 국내에 이미 스무 개 넘게 있는
1인용 임장 기록 앱 중 하나가 됩니다.

| | |
|---|---|
| 측정 대상 | 초대 발송 → 열람 → 수락 → 조건 입력 완료의 단계별 전환율 |
| 측정 방법 | 조건 대조 로직 없이, 목록 공유 + O/X 반응만 있는 최소 형태로 선행 측정 |
| 판정 기준 | 초대 수락률 `측정 필요` — 임계값은 제품 없이 확정 불가 |
| 거짓일 때 | 2인 전제를 재검토한다. 다만 1인 우선으로 뒤집는 안은 이미 기각했다 → `decisions/0002` |

### 국내 비교군 — 2026-08-18 조사로 확정

결혼준비 앱 3종이 **동일한 초대 메커니즘을 이미 운영 중**임을 확인했습니다.

| 앱 | 초대 방식 | 신혼집 관련 기능 |
|---|---|---|
| **특별시** | **6자리 초대 코드**로 두 사람 연결, 실시간 공유 | "예산도, 취향도, **신혼집도 함께 정하고**" — 명시 |
| 웨딩노트 | 파트너 초대 → 같은 노트를 둘이 작성 | 신혼집 예산·구매 목록 함께 정리 |
| MarryNote | 파트너와 지출 공동 확인 | 신혼집 예산 별도 관리, **전세·매수·자가별 카테고리 자동 구성** |

**함의가 양방향입니다.**

- **긍정** — 예비부부 대상 2인 초대가 실제로 작동한다는 존재 증명. H1의 전제 자체는 비현실적이지 않습니다.
- **경고** — 이들은 이미 관계가 형성된 두 사람을 확보했고 신혼집 영역에 발을 걸치고 있습니다.
  다만 그들이 하는 것은 **예산 관리**이지 매물 비교나 조건 충돌 계산이 아닙니다.
  → `docs/04-benchmarks.md` Tier 2

**확정 불가**: 이들의 실제 초대 수락률은 비공개입니다.
임계값은 여전히 우리가 직접 측정해야 합니다.

**측정 순서상 가장 먼저 옵니다.** 조건 대조와 비용 환산을 다 만든 뒤에
초대가 안 된다는 걸 알게 되면 그때까지의 작업이 전부 매몰됩니다.

## H2 — 2인 집찾기에서 갈등과 반복 비교가 충분히 큰 문제다

**상태: 셋으로 쪼갰고 둘이 확정됐다 — 남은 것은 "지연"뿐**

원래 가설이 세 주장을 묶고 있었습니다. 하나씩 분리해야 어디까지 아는지가 드러납니다.

```
H2-a    반복 비교가 실재한다          ✅ 확정 (당근부동산 실측)
H2-b-1  2인 조건 충돌이 실재한다      ✅ 확정 (Zillow 조사)
H2-b-2  그 충돌이 결정을 지연시킨다    ❓ 미검증 — 여기만 남았다
```

### H2-a — 반복 비교가 실재한다 → **확정**

당근부동산 조사(2026-05, 971명) 기준:

- 전세 계약자는 **2.5개월 동안 4.1곳**을 둘러본 뒤 계약
- 30대는 **2.7개월, 4.1곳** — 전 연령대 중 가장 오래 탐색
- 20대는 1.4개월로 가장 짧음

**두 달 넘게 네 곳을 비교하는 행동은 실재합니다.**
이 정도 기간과 개수면 기억에만 의존할 수 없고, 기록·비교 도구가 필요한 규모입니다.

### H2-b-1 — 2인이 집 고를 때 조건 충돌이 실재한다 → **확정**

Zillow Research 조사(2020-02) 기준:

- **미국인 77%가 지난 10년간 파트너와 집을 사며 다퉜다**
- 다툰 항목 — 크기·스타일 **54%** · **must-have/deal breaker 47%** · 위치 **42%** · 예산 **37%** · 수리 **29%**

**상위 세 항목이 전부 조건 충돌입니다.** 예산(37%)보다 앞섭니다.
우리가 판정에 넣기로 한 것(통근·면적·주차·역 도보)이 정확히 이 범주입니다.

**한계를 함께 적습니다.** 미국·2020년·**매매** 기준이고(우리는 전월세),
원문이 403으로 막혀 표본 크기를 확인하지 못했으며, 같은 조사에서 **60%가 "결국 상관없었다"** 고 답했습니다.

> **그럼에도 확정으로 둡니다.** "결국 상관없었다"는 **사후 회고**이지 그 시점에 충돌이 없었다는 뜻이 아닙니다.
> 그리고 이 문제를 다루는 서비스가 실제로 만들어져 쓰이고 있습니다(TwoKeys · 결혼준비 앱 3종 — `04-benchmarks.md`).
> **다투고, 그것을 다루는 도구에 사람이 돈과 시간을 쓴다면 충돌은 실재합니다.**

→ `03-evidence-log.md` F26

### H2-b-2 — 그 충돌이 결정을 지연시킨다 → **미검증 · 급소**

**여기가 비어 있습니다.** 충돌이 있다는 것과 그것이 결정을 늦춘다는 것은 다른 주장입니다.

당근부동산 조사는 **1인 기준 탐색 행동**만 보여주고,
2인 탐색 기간을 1인과 비교한 통계는 **국내외 어디에도 없습니다**(`03-evidence-log.md` §찾아봤으나 없는 것).

| | |
|---|---|
| 측정 방법 | 최근 6개월 내 2인 이상이 함께 집을 구한 사용자 인터뷰 |
| 판정 기준 | "상대와 의견이 갈려 결정이 지연된 경험"이 **과반** + **지연 원인에서 `조건 충돌` > `일정 조율`·`비용 분담`** |
| 왜 원인까지 묻나 | 둘이라 늦어지는 이유는 넷일 수 있습니다 — 조건 충돌 · 일정 조율 · 승인 단계 추가 · 예산 합의 선행. **우리는 첫째만 풉니다** |
| 표본 조건 | **완전공동형만.** 주도–승인형은 우리 제품이 작동하지 않는 세그먼트라 제외 (`03-evidence-log` I12) |
| 거짓일 때 | 문제 정의를 다시 쓴다. 비교가 어려운 것이 문제인지, 애초에 후보를 못 찾는 것이 문제인지 재확인 |

문항 설계는 `03-evidence-log.md` §A1에 있습니다.

**주의 — 국내에 이 문제를 다루는 제품이 없다는 사실은 수요의 근거가 아닙니다.**
미개척의 근거일 뿐이며, 시장이 없어서 비어 있을 가능성도 같은 무게로 존재합니다.

## H3 — 사용자가 출근지·예산·대출조건을 입력할 의향이 있다

**상태: 설계로 완화 가능**

| | |
|---|---|
| 측정 대상 | 조건 입력 시작 대비 완료율, 항목별 이탈 지점 |
| 완화 설계 | 온보딩에서 한꺼번에 묻지 않는다. **출근지는 통근 시간을 볼 때, 대출 조건은 실질 비용을 볼 때** 받는다 |
| 유리한 조건 | 네이버는 로그인 사용자 기반과 전월세대출 비교를 이미 갖고 있어 입력 부담이 상대적으로 낮다 |
| 판정 기준 | 조건 입력 완료율 `측정 필요`. 국내 선행 사례는 손품노트(예산·출퇴근 동선·선호조건을 이미 받고 있음) |
| 거짓일 때 | 필수 입력 항목을 출근지 하나로 줄이고 나머지는 선택으로 전환 |

## H4 — 보유 매물 데이터만으로 의미 있는 비용 비교가 가능하다

**상태: 부분적으로 불가 — 그리고 그 사실이 설계를 결정한다**

| 가진 것 | 없는 것 |
|---|---|
| 보증금, 월세 | 실제 대출 심사 결과와 금리 |
| 관리비(표시분) | 관리비 세부 내역 |
| 위치, 확인매물 여부 | 교통비 |

| | |
|---|---|
| 대응 | 앞의 둘은 **전제 공개**로 다루고, 교통비는 출근지 입력으로 직접 계산한다 |
| 측정 방법 | 사용성 테스트에서 "이 숫자를 믿을 수 있는가"를 직접 묻는다 |
| 판정 기준 | **전제 문구를 본 뒤 신뢰도가 오히려 오르는지.** 내려가면 전제 공개 방식이 잘못된 것 |
| 거짓일 때 | 비용 비교를 절대값이 아닌 상대 차액(A가 B보다 월 얼마)만 제시하는 형태로 후퇴 |

환산식과 전제 목록은 [`06-cost-model.md`](06-cost-model.md).

## H5 — 매물 회전이 비교 주기보다 느리다

**상태: 부분 확정 — 그리고 실측이 초기 설정을 일부 반박했다**

### 확정된 실측 (2026-08-18 조사)

당근부동산이 2026년 5월 11~17일, 두 달간 거래를 완료한 이용자 971명을 조사한 결과:

| 거래 유형 | 탐색 기간 | 방문 매물 수 |
|---|---|---|
| 매매 | 평균 3.6개월 | 4.3개 |
| 전세 | 평균 2.5개월 | 4.1개 |
| 월세 | 평균 1.8개월 | 3.5개 |
| **30대 (주 타깃)** | **2.7개월** | **4.1곳** |

### 이 데이터가 확인해준 것

**"최대 5개" 상한이 실제 행동과 일치합니다.**
사람들은 실제로 3.5~4.3개를 방문하고 계약합니다.
5개 제한은 임의로 정한 숫자가 아니라 실측 상단을 살짝 넘는 값입니다.
**초기 설정의 근거가 추측에서 데이터로 바뀌었습니다.**

### 이 데이터가 반박한 것

**"수명은 며칠"이라는 서술은 틀렸습니다.**
전체 탐색 여정은 **1.8~3.6개월**이고, 30대는 2.7개월입니다.
"장기 비교 보드가 아니다"라는 비목표를 문자 그대로 유지하면 실제 사용 기간과 어긋납니다.

### 수정된 이해

두 개의 시계를 구분해야 합니다.

| 시계 | 길이 | 무엇이 살아남나 |
|---|---|---|
| **비교 세션** (후보 5개 → 방문 2개) | 며칠 | 후보 목록 — 회전한다 |
| **탐색 여정** (첫 검색 → 계약) | **2~3개월** | **조건 · 비교 근거 — 유지된다** |

즉 세션은 짧고, 여정은 길며, **여정 동안 세션이 여러 번 반복됩니다.**
매물은 회전하고 조건은 남습니다.

이것은 이미 내린 설계 결정을 오히려 뒷받침합니다 —
**조건을 매물이 아닌 사용자에 귀속**시키는 구조가 2~3개월을 버티게 하는 장치입니다.

| | |
|---|---|
| 판정 기준 | 후보 등록 → 방문 후보 확정까지의 **중앙값 < 매물 평균 게시 기간** |
| 남은 미측정 | 네이버페이 부동산 **매물 평균 게시 기간** — 내부 데이터, 외부 조사 불가 |
| 참고 | 2021년 수도권 과열기(매매수급지수 110 상회)에는 등록 후 평균 14일 내 소진. **과열기 수치라 현재 적용 부적절** |

**표본 한계**: 당근부동산 이용자 971명 기준이라 전체 시장 대표성은 제한적입니다.
직거래 성향 이용자가 과대 대표됐을 가능성이 있습니다.

## 측정 순서

```
H1 (초대 수락률)
  ├─ 거짓 → 중단하고 2인 전제 재검토
  └─ 참  → H3 (조건 입력 완료율)
             └─ H4 (비용 신뢰도) · H5 (수명) 병행
                  └─ H2-b-2 (지연 여부)는 인터뷰로 병행 가능
```

H2-b-2를 마지막에 둔 것은 중요도가 낮아서가 아니라,
정성 조사라 제품 없이도 병행할 수 있기 때문입니다.
