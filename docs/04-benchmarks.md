# 기준 서비스 · 참조 서비스

두 목록은 성격이 다릅니다.

- **기준 서비스** — 사용자가 우리 대신 쓸 수 있는 것. **측정 대상**
- **참조 서비스** — 우리가 구조를 빌려올 것. **설계 대상**

같은 서비스가 양쪽에 들어가기도 하며, 그때는 역할이 다릅니다.

# 기준 서비스

## Tier 0 — 진짜 대체재

지금 사용자가 **실제로** 쓰고 있는 것. 여기서 못 이기면 나머지는 의미가 없습니다.

| 서비스 | 겹치는 것 | 무엇을 기준으로 삼나 |
|---|---|---|
| **카카오톡** | 매물 링크 공유, 의견 교환, 사실상의 공동 후보 목록 | **초대에서 첫 반응까지 걸리는 시간.** 카톡은 3초. 30초를 넘기면 진다 |
| **노션 / 엑셀 템플릿** | 매물 비교표, 항목별 기록 | **6개 항목 입력 소요 시간.** 노션 "좋은 집 구하기 템플릿", 월부 단지임장 양식이 유통 중 |
| **지도 앱 + 메모장** | 통근 시간 확인, 장단점 기록 | 매물당 앱 간 왕복 전환 횟수 |

Tier 0을 맨 위에 두는 것이 핵심입니다.
**경쟁 상대는 다른 부동산 앱이 아닙니다.**

## Tier 1 — 기능이 직접 겹치는 것

| 서비스 | 겹치는 것 | 무엇을 기준으로 삼나 |
|---|---|---|
| **집노트** | 8개 항목 5점 척도, 2배 가중치, 0~100 종합점수, 온디바이스 | 채점 입력의 마찰. **그리고 "총점을 내지 않는다"는 결정의 반대 사례** — 이쪽이 더 잘 팔리면 `decisions/0001`이 틀린 것 |
| **임장노트** | 매물 병렬 비교, PDF 리포트 공유 | 비교 화면의 정보 밀도. PDF 공유가 우리 초대 대비 얼마나 편한가 |
| **손품노트** | 예산·출퇴근 동선·선호조건 입력 → 추천, 항목별 평가 | **H3(조건 입력 완료율)의 유일한 국내 선행 사례.** 출퇴근 동선을 이미 받고 있음 |
| **주인장** | 입지/공용/실내 체크리스트 → 리포트, 노트 간 비교 | 체크리스트 항목 설계 — 무엇을 묻고 무엇을 안 묻는가 |
| **임장일기** | 매물 카드를 배우자·가족·중개사에게 전송 | **단방향 공유의 상한선.** 우리 양방향이 확실히 나은지 |
| **LoopCV · AIApply** (채용 오퍼 비교) | LoopCV는 100점 스코어, AIApply는 “best option” 하이라이트 | **`decisions/0001`의 반대 사례.** 채용 오퍼 비교조차 대부분 총점을 쓴다 — 총점 미사용이 시장 관행에 역행함을 확인 |

## Tier 2 — 진입 위협 (관계와 유통을 이미 가진 쪽)

| 서비스 | 왜 위협인가 | 무엇을 기준으로 삼나 |
|---|---|---|
| **결혼준비 앱** — 특별시, 웨딩노트, MarryNote | **확인됨 (2026-08-18).** 특별시는 6자리 초대 코드로 두 사람을 연결하고 "신혼집도 함께 정하고"를 명시. MarryNote는 전세·매수·자가별 카테고리를 자동 구성. **매물 비교로 한 칸만 확장하면 경쟁자** | 초대 수락률 — **H1의 사실상 유일한 국내 비교군** (단 수치는 비공개) |
| **네이버페이 부동산 (현재)** | 관심매물·단지·지역 저장이 이미 있음 | 30일 이상 방치된 관심매물 비중의 **현재 baseline** |
| 직방 / 호갱노노 | AI 매물 추천 준비 중, 대화형 조건 추천 | 조건 입력을 어디까지 요구하고 이탈이 어디서 나는가 |
| 아실 | A아파트 vs B아파트 가격 차트 병렬 비교 | 비교 축이 가격 하나일 때의 한계 |

**결혼준비 앱이 Tier 2 최상단인 이유**:
우리가 H1을 검증해야 하는데, 저들은 **그 검증을 이미 끝낸 상태**입니다.
관계 형성이 끝난 두 사람에게 접근할 수 있다는 것이 구조적 우위입니다.

다만 **겹치는 범위는 아직 제한적**입니다 (2026-08-18 확인).

| 그들이 하는 것 | 우리가 하려는 것 |
|---|---|
| 신혼집 **예산** 관리 | 신혼집 **매물** 비교 |
| 거주 형태별 지출 카테고리 | 조건 충족·충돌 계산 |
| 공동 체크리스트 | 양보 지점 서술 |

**금액을 담는 그릇은 있으나 매물을 대조하는 로직은 없습니다.**
이 격차가 좁혀지는지가 감시 지표입니다.

# 참조 서비스

경쟁자가 아니라 **패턴 공급처**입니다.

## H1 · 두 번째 사용자를 들여보내기 — 최우선

| 서비스 | 빌려올 것 |
|---|---|
| **위밋플레이스 / 모이삼** | **링크 하나로 상대가 출발지만 입력하고 끝. 가입 없음.** 우리 초대 플로우가 그대로 따라야 할 형태 |
| 모여봐요 / 타임테이블2 | 초대 링크 → 상대가 자기 조건(가능 시간)만 찍고 이탈 → 그래도 결과가 나옴 |
| 트루비 | 초대코드 하나로 같은 공간 진입, 의견 갈릴 때 익명 투표 |
| 함쓰 · 스태시바이 · 듀오로그 | 국내에서 **2인 공유가 실제로 지속되는** 몇 안 되는 카테고리(가계부·북마크·사진). 초대 후 리텐션 구조 |

## 개인 조건 N개 → 하나의 해로 수렴

| 서비스 | 빌려올 것 |
|---|---|
| **위밋플레이스 / 모이삼** | **구조가 동형.** 각자 출발지(=개인 조건) → 최적 지점 계산 → 후보 제시. 우리는 출발지가 출근지로, 중간지점이 매물로 바뀔 뿐 |

참조 목록에서 가장 중요한 항목입니다.
우리가 만들려는 계산 구조를 국내에서 이미 검증한 유일한 사례입니다.

## 조건 입력 부담 낮추기 (H3)

| 서비스 | 빌려올 것 |
|---|---|
| cozymate | 24개 라이프스타일 항목을 이탈 없이 받아내는 방식 |
| 한집친구 | 생활패턴·예산·청결도·흡연을 매칭 점수로 환산하는 항목 설계 |
| 폴잇 | 가치관 입력을 부담이 아니라 재미로 만드는 프레이밍 |

## 충돌 · 트레이드오프 표현 — ✅ 해소 (2026-08-19)

**국내 부동산에는 참조할 것이 없었고, 의료에 있었습니다.**
초판에 "참조가 얇다"고 적었던 칸이 `05-tradeoff-patterns.md` 조사로 채워졌습니다.

| 서비스 · 표준 | 빌려올 것 |
|---|---|
| **IPDAS** (국제 환자 의사결정보조자료 표준) ★ | **총점 없이 옵션을 균형 있게 제시하는 국제 표준.** *"어떤 옵션도 다른 옵션보다 선호하지 않는 방식"* 이 정의 자체 |
| **Option Grid** ★ | IPDAS의 화면 형식. **1페이지 표, 점수·순위·추천 표시 없음.** 우리 ⑦ 비교 표의 원형 |
| **MaxOfJob** (채용 오퍼) | 항목별 side-by-side, **총점 없음** — 드문 사례 |
| 저니피키 | 플래너 '토론장' — 의견이 갈린 상태를 다투지 않게 담는 UI |
| 트루비 | 익명 투표로 대립을 중화하는 장치 |

**우리 축은 Option Grid와 다릅니다** — 저쪽 열은 *선택지*, 우리 열은 *사람*입니다.
형식은 빌리되 행에 무엇을 둘지는 우리가 정합니다. 우리 행은 **"조건"** 입니다.

남은 것은 **요금제 비교 도메인** 하나뿐입니다(보험은 업계 블로그 수준으로 일부 확인).
