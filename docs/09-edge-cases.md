**판정 기준** — MVP 필수는 *정상 플로우에서 실제로 자주 발생 + 없으면 사용자가 막힘*.

## MVP 필수 다섯

`01-team-brief.md` §6과 `assets/reverse-planning.html` 13번에 반영됨.

| 상황 | 처리 | 왜 필수인가 |
|---|---|---|
| **B가 초대에 안 들어옴** | **1인 빈 경로** — A는 자기 조건 판정·실부담·통근을 혼자 봄. 교통비는 1인분만 반영됐다고 표시 | H1이 최우선 미검증이므로 **가장 흔한 경로일 수 있음.** 여기서 A가 아무것도 못 보면 H1 실패가 제품 전체를 죽인다. 빈 경로가 있으면 "2인 기능 미성립"으로 격리된다 → `decisions/0002` |
| **B가 조건 입력 중 이탈** | 넣은 것만으로 부분 판정. "B의 필수 ②가 비어 있음" 표시 | H1-c 깔때기의 측정 지점. 부분 입력을 버리면 어디서 멈췄는지 모른다 |
| **매물이 나감** (거래완료·삭제) | 후보에서 빠지되 **조건은 그대로 남고** 나머지는 판정 유지 | 탐색 여정이 2~3개월인데 매물은 회전한다(H5). 조건이 살아남는 걸 사용자가 실제로 보게 되는 지점 → `decisions/0003` |
| **5개 전부 불충족** | 막다른 길 → **조건 완화로 연결** | 필수 2개 × 2인 = 4개를 동시에 만족하는 매물은 드물다. **FT6이 이 화면의 유일한 출구다** |
| **조건이 물리적으로 모순** | "A 강남역 20분 · B 여의도역 20분 — 두 범위가 겹치지 않습니다" + 완화 제안 | 원인을 모르면 "왜 아무것도 안 나오지"로 끝난다 |

## 후순위 여덟

문서에 넣지 않았으나 구현 전에 결정해야 할 것들.

| 상황 | 처리 방향 | 왜 후순위인가 |
|---|---|---|
| **5개 전부 둘 다 충족** | "논의할 지점이 없습니다. 방문 순서만 정하세요" | 서비스 가치가 0이 되는 경우지만 **문제가 아니라 좋은 상태.** 사용자가 막히지 않는다 |
| **후보 0~1개** | 빈 상태 안내 + 관심매물로 돌려보내기 | 진입 전 상태라 판정 로직과 무관 |
| **6개째 담으려 함** | 5개 제한 안내 + 교체 유도 (무엇을 뺄지 선택) | 상한 근거는 실측(방문 3.5~4.3개)이라 견고하나, 초과 시 UX는 나중에 정해도 됨 |
| **A가 조건을 나중에 바꿈** | 전체 재판정 — FT6과 같은 로직 | 이미 FT6에 포함됨. 별도 설계 불필요 |
| **통근 경로가 안 나옴** (도서지역 등) | 계산 불가로 표시. **미충족이 아님** | 수도권 1차 타깃에서는 거의 발생 안 함. 단 *"계산 못 함 ≠ 조건 미달"* 원칙은 `확인 필요` 층과 동일하게 지켜야 함 |
| **관리비·준공연도 미표기** | `확인 필요` 처리 | 이미 FT4의 네 번째 상태에 포함 |
| **B가 나중에 나감 / 관계 종료** | 데이터 처리 정책 필요 — 조건은 누구 것인가, 후보 목록은 남는가 | 개인정보 처리 판단이 필요해 별도 검토. **출시 전에는 반드시 정해야 함** |
| **계약 완료 후** | 서비스 종료 · 데이터 보관 기간 | 종료점(방문 후 유지·보류·제외) 밖 |

## 원칙 하나

**계산 못 하는 것과 조건에 미달하는 것은 다르다.**

매물 데이터가 없거나(반려동물), 경로 계산이 실패하거나, 값이 표기되지 않은 경우
전부 `미충족`이 아니라 **`확인 필요` 또는 `계산 불가`** 로 처리한다.
없는 걸 "안 됨"으로 판정하면 후보가 잘못 탈락한다.
