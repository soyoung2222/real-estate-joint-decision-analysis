## 여기서 읽히는 것 셋

**① B의 감정은 시작부터 낮다.**
A는 자기가 찾은 집이라 기대가 있지만, **B는 부탁받아 들어온 사람**이라 첫 접점(②)부터 부담이다.
CJM을 1인으로 그리면 이 격차가 안 보이고, 그러면 **B를 A와 같은 동기를 가진 사람으로 착각한 설계**가 나온다.
원문 14번 화면에 B 경로가 없었던 것이 정확히 그 결과다.

**② ③에서 B의 피로가 누적되고 ⑥에서 회피로 바뀐다.**
B는 매물마다 링크를 열어 스스로 판단해야 하는데, **판단 기준을 말로 설명할 방법이 없다.**
그래서 가장 비용이 낮은 답을 고른다 — “그냥 별로.”
**회피는 성격이 아니라 구조의 결과다.**

**③ ⑥만 성격이 다르다.**
②③④⑤⑦은 *시간이 드는* 단계이고 ⑥은 *멈추는* 단계다.
⑥에서 막히면 ③④⑤에 쓴 노력이 전부 무효가 되고 ⑧로 간다.

## TO-BE에서 각 단계가 어떻게 되나

| AS-IS | TO-BE | B의 감정 변화 |
|---|---|---|
| ② 링크 3개 전송 | 초대 **1회** | 😕 → 😐 요청이 한 번뿐 |
| ③ 하나씩 열람 | **사라짐** (자동 판정) | 😖 → — 열어볼 필요 없음 |
| ④⑤ 각자 계산 | 판정에 포함 | — |
| **⑥ “그냥 별로”** | **조건 4번 입력 → 판정이 대신 말함** | 😑 → 🙂 **설명 부담이 사라짐** |
| ⑦ 개인 메모 | 방문 후 공동 기록 | — |

**B가 얻는 진짜 값은 “좋은 집을 찾는 것”이 아니라 “설명하지 않아도 되는 것”이다.**
이게 초대 문구에 들어가야 할 내용이기도 하다.

# 2. 기회점수 (Opportunity Score)

## 공식

Ulwick의 Outcome-Driven Innovation 기준.

```
OS = 중요도 + max(중요도 − 만족도, 0)      (각 10점 척도)

OS ≥ 12   과소서비스 — 기회
10 ~ 12   적정
OS < 10   과잉서비스 — 이미 충분하거나 과함
```

## 지금 점수를 매기지 않는다

**중요도·만족도 실측이 없다.** 여기에 숫자를 채우면 가드레일 G6 위반이다.

> **금지** | 못 재는 숫자를 지어내지 않는다. 내부 데이터가 필요한 지표는 `측정 불가`로 표기한다.

대신 **상대적 위치는 지금 가진 근거로 논증할 수 있다.**

## 대리 지표로 상대 위치 잡기

| 축 | 대리 지표 | 근거 |
|---|---|---|
| **만족도** | **대체재가 있는가** | 대체 수단이 있으면 만족도가 0은 아니다 |
| **중요도** | **실패했을 때 결과** | 실패가 전체를 무효화하면 중요도가 높다 |

| 단계 | 대체재 | 실패 시 | 만족도 | 중요도 | OS 상대 위치 |
|---|---|---|---|---|---|
| ① 저장 | 네이버가 직접 함 | 후보를 못 모음 | **높음** | 높음 | 낮음 — 손대지 않는다 |
| ② 공유 | 카카오톡 (3초) | 상대가 못 봄 | 높음 | 중간 | 낮음 |
| ③ 열람 | 네이버 (따로) | 판단 못 함 | 중간 | 중간 | 중간 |
| ④ 통근 확인 | 지도 앱 | 대략 감으로 | 중간 | 중간 | 중간 |
| ⑤ 비용 계산 | 계산기 5종+ 무료 | 대략 감으로 | 중간 | 중간 | 중간 |
| **⑥ 의견 교환** | **없음** | **전체가 무효화되고 ⑧로 회귀** | **최저** | **최고** | **최고 ★** |
| ⑦ 메모 | 메모장·노션 | 기억에 의존 | 중간 | 낮음 | 낮음 |
| ⑧ 재탐색 | 네이버 | 순환 | 높음 | — | — |

**⑥의 OS가 가장 높다는 것은 근거로 논증된다.** 절대 점수는 여전히 `측정 필요`다.

```
만족도 최저 근거   국내 부동산에 대응 수단 없음. 충돌 표현 참조군도 부동산 밖(의료)에서 찾아야 했음
중요도 최고 근거   ⑥에서 멈추면 ③④⑤의 결과가 전부 버려지고 ⑧로 돌아감 (I1·I2)
```

반대로 **②③④⑤⑦은 OS가 중간**이다. 대체재가 이미 작동하고 있어서 만족도가 바닥이 아니다.
**여기에 기능을 넣어도 카톡+노션을 이길 이유가 약하다** — 10번 차별점의 결론과 같은 지점에 도착한다.

## 실측 설계

H2-b 인터뷰와 **같은 표본에서 동시에 수집**하면 추가 비용이 거의 없다.

| | 내용 |
|---|---|
| 표본 | 최근 6개월 내 **2인 이상이 함께** 집을 구한 사람 |
| 문항 A | 각 단계에 대해 — “이 일이 잘 되는 게 얼마나 중요했나요?” (1~10) |
| 문항 B | 각 단계에 대해 — “실제로 얼마나 잘 됐나요?” (1~10) |
| 산출 | 단계별 OS. **⑥이 실제로 최고인지 확인** |
| 반증 | ⑥보다 ④⑤(통근·비용)의 OS가 높게 나오면 → **우리는 계산기를 만들어야 한다.** 그 경우 Hero Feature 재검토 |

**반증 조건을 미리 적어두는 게 이 분석의 핵심이다.** OS를 재놓고 결과에 맞춰 해석하면 의미가 없다.

### R1을 쪼갠다 — 무엇을 볼 것인가

“외부 서비스 UI 탐색”은 그대로는 실행할 수 없다. 볼 것을 미리 정해야 한다.

| 서비스 | 볼 화면 | 우리 어느 화면에 쓰나 | 측정할 것 |
|---|---|---|---|
| **위밋플레이스** | 초대 링크 → 상대 진입 → 출발지 입력 → 결과 | **③ 초대 · ② 조건 입력** | **링크 열고 입력 끝낼 때까지 몇 탭, 몇 초** |
| 위밋플레이스 | 결과 화면의 후보 제시 방식 | ④ 후보 목록 | 총점을 쓰는가, 순위를 매기는가 |
| **특별시 / 웨딩노트** | 6자리 초대 코드 발급 → 연결 | ③ 초대 | **관계 형성된 2인에게 초대를 어떻게 파는가** (문구) |
| 집노트 | 8항목 채점 화면 | **반대 사례** | 40번 입력이 실제로 얼마나 걸리는가 |
| cozymate | 24개 항목 입력 | ② 조건 입력 | 이탈 없이 받아내는 장치 |
| Airbnb | 공동 위시리스트 초대 | ③ 초대 | — |

**각 항목에 “측정할 것”이 붙어야 탐색이 감상으로 끝나지 않는다.**
특히 위밋플레이스의 **탭 수·소요 시간**은 Tier 0 카톡(3초)과 직접 비교할 수 있는 유일한 수치다.
