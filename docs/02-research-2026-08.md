# 인접 서비스 조사 — 2026.08

**조사일**: 2026-08-14
**방법**: iTunes Search API (KR 스토어) 7개 키워드 스캔 · 디스콰이엇 프로덕트 페이지 직접 열람 · 웹 검색

## 결론

**"두 사람 조건을 각각 등록 → 매물별 충족/충돌 계산 → 누가 무엇을 양보하는지 제시"하는
서비스는 국내에 없다.**

개인용 채점 앱은 최근 1년 사이 급증했고, 공유는 전부 **단방향**에서 멈춘다.

### 핵심 관찰

**채점·가중치는 이미 있다.**
집노트의 "중요 항목 2배 가중치 + 미평가 제외"는 사실상 개인용 MCDA다.
즉 조건 모델링 자체는 차별점이 아니다. → `decisions/0001-no-total-score.md`

**전부 1인분이다.**
계정·로그인 없는 온디바이스 설계가 다수(집노트·방찾기 기록·임장일기)라
**구조적으로 2인 조건을 담을 수 없다.**

**"공유"의 실체는 전부 단방향이다.**

| 앱 | 공유 방식 | 상대가 조건을 입력하는가 |
|---|---|---|
| 임장일기 | 매물 카드 *전송* | ❌ 보기만 |
| 임장노트 | **PDF 1장** 내보내기 | ❌ |
| 방찾기 기록 | 상세 화면 *캡처* | ❌ |
| 집노트 | 비교표로 "가족과 의논" | ❌ 앱 밖에서 |
| 임장프렌드 | 임장 루트·기록 공유 | ❌ 조건 대립 개념 없음 |

**상대방이 자기 조건을 입력하는 자리가 어디에도 없다.**

## 2. 디스콰이엇 — 프롭테크 프로덕트 6종, 전부 1인 기준

| 프로덕트 | 정의 | 판정 |
|---|---|---|
| 주인장 | 임장 기록 + 체크리스트 리포트 | 1인 기록 |
| 찾집 | 조건 등록 → 중개인이 매물 역제안 (역경매) | **조건 1인분** |
| 집구하기가치가 | 발품 동행·사전 점검 (사람이 대신 감) | 오프라인 대행 |
| 집업 (데브디) | **1인가구** 맞춤 주거이전 플래너 | 명시적으로 1인 |
| cozymate | 24개 라이프스타일 기준 **룸메이트 매칭** + 역할·규칙 설정 | 사람 매칭이지 집 선택 아님 |
| 내집스캔 | 전세사기 예방 점검 | 무관 |

cozymate가 유일하게 "두 사람 조건을 맞춘다"에 근접하지만 **대상이 매물이 아니라 사람**이다.

> "마음 맞는 룸메이트를 먼저 찾고, **함께 살 방은 그다음에** 정하세요"
> — cozymate / 한집친구 소개 문구

**그 '그다음'을 맡은 제품이 국내에 없다.**

## 4. 인접 도메인 — 같은 구조가 이미 검증됨

| 영역 | 서비스 | 구조 |
|---|---|---|
| 일정 | 모여봐요, 타임테이블2, 모두의 시간 | N명 가능시간 → 교집합 |
| 장소 | **위밋플레이스, 모이삼** | **N명 출발지(=개인 조건) → 최적해 계산** |
| 여행 | 저니피키, 트루비 | 초대 → 후보 공유 → 투표 |
| 룸메이트 | 한집친구, cozymate | 생활패턴·예산 → 매칭 점수 |
| 결혼준비 | 웨딩노트, 특별시, MarryNote | **2인 초대가 이미 작동 중** (아래 §4-1) |

**"N명 조건 → 하나로 수렴"은 국내에서 이미 여러 번 만들어진 패턴이다.**
금액이 가장 크고 갈등 비용도 가장 큰 주거만 비어 있다.

위밋플레이스·모이삼은 구조가 동형이다 —
출발지가 출근지로, 중간지점이 매물로 바뀔 뿐. → `docs/04-benchmarks.md`

## 4-1. 결혼준비 앱 — 추가 조사 (2026-08-18)

초판에서 "이름·키워드만 확인, 판정 근거가 얇음"으로 남겼던 항목을 확정했다.
**세 앱 모두 2인 초대가 작동 중이고, 셋 다 신혼집 영역에 이미 발을 걸치고 있다.**

| 앱 | 최근 업데이트 | 초대 방식 | 신혼집 기능 |
|---|---|---|---|
| **특별시** | 2026-07-06 | **6자리 초대 코드**로 연결, 실시간 공유 | "예산도, 취향도, **신혼집도 함께 정하고**" |
| **웨딩노트** | 2026-08-14 | 파트너 초대 → 같은 노트 공동 작성 | 신혼집 예산·구매 목록 함께 정리 |
| **MarryNote** | 2026-07-26 | 파트너와 지출 공동 확인 | 신혼집 예산 별도 관리, **전세·매수·자가별 카테고리 자동 구성** |

### 판정

**위협도 상향.** 다만 겹치는 범위는 제한적이다.

| 그들이 하는 것 | 우리가 하려는 것 |
|---|---|
| 신혼집 **예산** 관리 | 신혼집 **매물** 비교 |
| 거주 형태별 지출 카테고리 | 조건 충족·충돌 계산 |
| 공동 체크리스트 | 양보 지점 서술 |

즉 **금액을 담는 그릇은 있으나 매물을 대조하는 로직은 없다.**
그러나 관계가 형성된 두 사람과 초대 채널을 이미 확보했다는 점에서,
확장 시 가장 빠르게 도달할 수 있는 위치에 있다.

### 우리 가설에 주는 영향

- **H1 긍정** — 예비부부 대상 2인 초대는 실제로 작동한다. 전제 자체가 비현실적이지 않다.
- **H1 확정 불가** — 이들의 실제 초대 수락률은 비공개. 임계값은 직접 측정해야 한다.

## 5. 사용자 탐색 행동 실측 (2026-08-18 추가)

당근부동산 조사 — 2026년 5월 11~17일, 두 달간 거래 완료 이용자 **971명**.

| 거래 유형 | 탐색 기간 | 방문 매물 수 |
|---|---|---|
| 매매 | 3.6개월 | 4.3개 |
| 전세 | 2.5개월 | 4.1개 |
| 월세 | 1.8개월 | 3.5개 |
| **30대** | **2.7개월** | **4.1곳** |
| 20대 | 1.4개월 | — |

**"최대 5개" 상한이 실측과 일치한다.** 실제 방문 수가 3.5~4.3개이므로
5개는 임의값이 아니라 실측 상단을 살짝 넘는 값이다.

**동시에 "수명은 며칠"이라는 초판 서술을 반박한다.**
전체 탐색 여정은 2~3개월이다. → `docs/01-hypotheses.md` H5의 수정된 이해

**표본 한계**: 당근부동산 이용자 기준이라 직거래 성향이 과대 대표됐을 수 있다.
