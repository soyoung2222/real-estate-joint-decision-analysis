## 기능 이름


**`같이 보기`** 로 확정한다. 사이드바에서는 설명 문구 `둘이서 보러 갈 집 정하기` 를 붙여 쓴다.

```
관심부동산
  같이 보기
  둘이서 보러 갈 집 정하기
   ✓ 후보 담기 · 예산 · 출근지 · …
```

| 항목 | 결정 |
| --- | --- |
| 작명 문법 | **순우리말 + `~기`.** `길찾기`·`장보기`·`함께보기` 계열. 한자어(`공동 의사결정`·`조건 협의`)와 `스마트~`·`AI~` 를 쓰지 않는다 — 둘 다 더 낡아 보인다 |
| 이름이 지는 부담 | **할 일까지만.** `길찾기` 가 경로 알고리즘을 설명하지 않듯, 차별점은 이름이 아니라 **설명 문구**가 진다 |
| 판정 기준이 된 자리 | **카톡 초대 문장.** `A님이 같이 보기에 초대했어요` 가 어색하면 이름이 틀린 것이다 — H1 초대 수락률이 이 제품의 급소다 |
| 함께 쓰는 동사 | 초대·진입 문구는 `같이 볼` 로 맞춘다 (`같이 볼 사람에게 링크를 보내세요`) |
| 단계 이름과의 관계 | 기능은 `같이 보기`, 종료점 화면은 `보러 갈 집 정하기`. **동사를 다르게 두어** 둘이 안 겹치게 한다 |

**설명 문구가 필수인 이유.** `보기` 는 부동산에서 `집을 보러 간다`(임장)로 읽혀 종료점과 맞지만,
`화면을 같이 본다`(= 공동 찜)로도 읽힌다. 공동 찜과 이름만으로는 구분되지 않으므로
설명 문구를 이름과 같은 자리에 둔다.

**G5 가드레일 예시를 바꿨다.** `“지도에서 같이 보기”` 가 위반 예시였는데 기능 이름과 충돌해
`“지도에서 같이 검색하기”` 로 고쳤다 (`01-team-brief.md`). 위반의 본질은 `보기` 가 아니라
**탐색을 새로 만드는 것**이다.


## 판정 방식


| 항목       | 결정                                              |
| -------- | ----------------------------------------------- |
| 판정 등급    | **둘 다 충족 / 한쪽만 충족 / 둘 다 불충족 + `확인 필요`**         |
| 총점       | **만들지 않음.** 조건 간 합산 금지                          |
| 조건 소속    | **사람에 저장** (매물이 아니라)                            |
| 처음 요구하는 입력 | **예산 하나.** 출근지는 **출퇴근하는 경우만** 받는다. 1~2번으로 첫 결과가 나온다 |
| 판정 항목 | **여섯 — 예산·통근시간·역 도보(상한형) · 전용면적(하한형) · 주차(유무형) · 매물 유형(일치형)** |
| **출근지** | **선택.** 없는 사람이 있다(재택·무직·전업·은퇴). 없으면 통근·교통비를 안 재고 **비교표에서 그 행을 뺀다** — `계산 불가`와 구분 |
| 타입 | **넷 — 상한형 · 하한형 · 유무형 · 일치형.** 일치형은 매물 유형 때문에 신설, 미달 표현이 실제값(`빌라`) |
| 필수 조건 개수 | **0~4개, 사용자가 정함.** 고정하지 않는다. 상한 4는 양보 문장이 안 읽히는 지점 |
| **선호** | **판정하지 않고 카드로.** 자유 문장, **개수 상한 없음**. 사람에 붙고 매물에 안 붙음. 칩으로 입력을 돕고 저장은 문장 |
| **확인 필요** | 방문 **전** 중개사 질문 — 반려동물 · 즉시 입주 · 전입신고 · 근저당·융자 |
| **방문 체크리스트** | **방문 전에 받는다** — 가서 봐야 아는 것(층간소음·실제 채광·곰팡이·주차 난이도·주변 소음·내부 상태). 전원 공통, 고르지 않음. **다녀온 뒤에 주면 늦다** |
| 역 도보 | **시간(분)으로 받는다** — 데이터가 분 단위. 거리로 받으면 분속 가정이 늘어남 |
| 주차 | **판정은 있음/없음.** 화면에는 세대당 대수를 병기 — `주차 있음 (세대당 0.8대)`. 임계값으로 받지 않는 이유는 0.5와 0.8의 차이를 사용자가 감으로 정해야 하기 때문 (F29) |
| 양보 문장 상한 | 미충족 3개 이상이면 **조건 표시 순서로 앞 2개만 문장**, 나머지는 목록 |
| 얻는 것이 없으면 | **“대신” 절을 지운다.** 없는 장점을 지어내지 않는다 |
| 입력 방식    | **점진적 공개** — 1단계 예산(+출근지) → 즉시 결과 → 조건 추가 |
| 1단계 표시   | **값만** (임계값이 없으므로). 2단계부터 판정                    |
| 이동수단     | **받음** — 출근지 화면 토글. 기본값 대중교통. **출근지가 없으면 안 물음** |
| 조건 표시 순서 | **예산 → 통근 → 필수①~④ → 확인** 고정. 양보 문장의 “앞 2개”도 이 순서 |
| 미충족 정렬   | **위로 올리지 않음** — 좌우 비교가 깨짐                       |
| 확인 필요 상한 | **없음** — 판정에 안 들어가므로 판정을 흐리지 않는다. 쓸지 말지는 사용자 자유 |
| 확인 필요 배지 | 후보 목록 최소 · 상세 인라인 · **질문 카드 크게**                |

| 항목 | 결정 |
| --- | --- |
| **화면 문구의 수신자** | **화면에 들어온 사용자.** 안내문은 “이 화면이 무엇이고 지금 무엇을 하면 되는지”를 말한다. `FT4 · 자동 판정`, `North Star 달성`, `이 제품의 전부` 같은 역기획 언어는 제품 화면에 쓰지 않는다 |
| **설계 근거의 자리** | **접힌 노트(`설계` 배지)로 화면 하단에 분리.** 지우지 않는다 — “왜 4개 상한인가”, “왜 여기서 판정하지 않는가”는 팀에게 필요하다. 다만 사용자 문장과 같은 위계에 두면 안내문이 판정을 덮는다 |
| **B 마지막 화면** | **보고가 아니라 전환.** “저장했어요”로 끝내지 않고 로그인이 무엇을 남기는지(조건이 계정에 남음 · 새 매물 자동 대조 · 같이 정하기) 보여준다. 건너뛰면 30일 보관을 명시 |
| **모바일 뒤로가기** | **상단 좌측 `‹`.** 1단계에서만 감춘다. 앞으로만 가는 흐름은 조건 입력을 되돌릴 수 없게 만든다 |
| **기준값 입력 방식** | **숫자 입력(± 스테퍼 + 직접 타이핑).** 슬라이더는 “정확히 66㎡”를 못 맞춘다. min/max는 커밋 시점에만 자른다 — 타이핑 도중에 튀면 못 쓴다 |
| **슬라이더를 남기는 자리** | **조건 완화 미리보기 하나.** 여기서는 값을 정하는 게 아니라 *미달량 안에서 훑는* 동작이고, 트랙의 끝이 “여기까지만 풀 수 있다”를 몸으로 보여준다 |
| **콘텐츠 열** | **`--col:1040px` 하나의 축.** 진행바·본문·B 스테이지가 같은 좌우 축을 쓴다. 배경은 가로 전체, 내용만 열에 맞춘다(`.colpad`) — 래퍼 없이 `padding-inline:max(pad,(100%-col)/2)` |
| **읽는 폭** | **`--measure:62ch`, 열 폭과 별개.** 열이 1040이어도 본문이 1040으로 흐르면 12px 한글 80자가 된다. `.sub`·`.hint`·`.notice`·`.desc`·`.memo p`에 적용 |

**쟁점**

| 항목                           | 쟁점                                                                      |
| ---------------------------- | ----------------------------------------------------------------------- |
| **재탐색 필터 제안 화면 (A-13b-2)** ★ | **0건 분기의 절반이 아직 없다.** 프로토타입에도 빠져 있음. 핵심 8장에 포함시켰으므로 **가장 먼저 그릴 미설계 화면** |
| **조건 완화 화면 위치**              | 상세 판정 안인가 별도 화면인가                                                       |
| **매물 사진 노출 범위**              | 평가적 조건화 회피(G10) vs 매물 식별 편의                                             |
| 지도 판정 핀의 라벨 밀도               | 핀 5개에 실부담까지 붙이면 겹칠 수 있음                                                 |
| 점 플롯 축 처리                    | 조건마다 단위가 달라 한 화면에 놓기 어려움                                                |
| 필터 결과 수 표기                   | 정확한 수 vs 근사치(“약 30여 개”)                                                 |
