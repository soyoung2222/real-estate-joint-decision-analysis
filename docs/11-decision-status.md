# 2. 결정해야 하는 것

**리서치 없이 우리끼리 정할 수 있는 것들.**

## 사용자 데이터 수집 범위


| 항목                    | 쟁점                                                                                                          |
| --------------------- | ----------------------------------------------------------------------------------------------------------- |
| **필수 슬롯 — 몇 개 받을지, 뭘 받을지** ★ | **둘 다 미정.** 지금 2개인 건 *“더 받으면 남는 집이 없어서”* 다. 각자 3개씩이면 매물이 통과해야 할 조건이 6개가 되는데, 관심매물 5개 중에 그걸 다 통과하는 집은 사실상 없다. **다만 실제 매물로 세어본 적이 없어 잠정값이다** |
| **관계 수집 방식**          | H1 집단 비교에 필요하나 입력을 늘림 → **초대 링크에 심어 A가 고르는 안**                                                              |
| **실연비 입력 위치**         | 조정 가능하게 했는데 어디서 받나 — 조건 입력에 넣으면 입력 4번 압박                                                                    |
| **자차 통행료 입력 여부**      | 기본 0인데 받을지, 받으면 어디서                                                                                         |
| 입주 목표일 수집 여부          | 후보 정렬에 쓸지, 안 받을지                                                                                            |
| **B 비로그인 시 조건 보관 방식** | 코드에 묶어 임시 저장 · 세션 · 안 받음                                                                                    |

| 항목                           | 쟁점                                                                      |

# 3. 결정하려면 리서치가 필요한 것

**우리가 정할 수 없거나, 근거 없이는 못 정하는 것들.**

## 네이버 내부 사정 — 우리가 정할 수 없음


| 항목                      | 왜 막히나                       |
| ----------------------- | --------------------------- |
| **관심매물 조회 API 존재·권한**   | 안 되면 후보를 못 담음 — **제품의 전제**  |
| **공유 객체 비로그인 열람 가능 여부** | **H1 깔때기의 로그인 위치가 여기서 정해짐** |
| 검색 결과 수 조회 가능 여부·부하     | 안 되면 결과 수 미리보기를 뺌           |
| 검색 필터 URL 파라미터 규격       | 필터 전달 구현 방식                 |
| 경로 API 비용·쿼터            | 회차 반복까지 하면 호출량 누적           |
| 관심매물 방치 비중 baseline     | **원리적 확정 불가** — 내부 데이터      |


> **해소됨** — 대중교통 경로 API 리스크는 내렸다. 네이버 내부에는 지도 대중교통 엔진이
> 있고, 팀 프로토타입은 ODsay Basic(일 1,000 호출 무료)으로 충분하다(F25).
