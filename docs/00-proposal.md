# 같이 고르는 집 — 기능 제안

네이버페이 부동산 안에 넣는다고 가정하고 쓴 역기획입니다.
네이버와 무관한 개인 작업입니다.

**아직 안 만들었습니다.** 화면으로 본 버전: `assets/proposal.html`

---

## 한 줄로

> 둘이서 관심매물 5개를 놓고, 이번에 보러 갈 2개를 정한다.

어느 집이 더 좋은지 점수 매기는 게 아닙니다.
**A를 고르면 누가 뭘 포기하게 되는지를 눈에 보이게 만드는 것**입니다.

---

## 1. 지금 뭐가 문제인가

### 저장하고 나면 앱을 떠난다

```
찜하기 → 카톡으로 링크 보내고 → 지도로 출퇴근 재보고
       → 대출 계산기 켜고 → 중개사한테 전화하고
       → 방문 날짜 잡고 → 메모장에 장단점 적고
```

이 결과가 앱으로 돌아오지 않습니다. 남는 건 오래된 찜 목록입니다.

### 둘이 구하면 문제가 하나 더 있다

**상대가 뭘 원하는지 한 번도 말한 적이 없습니다.**

> "그 집 어때?"
> "음… 그냥 별로야"

여기서 끝납니다. 그리고 다음 매물에서 또 처음부터 시작합니다.

### 그래서 경쟁 상대가 다르다

이건 새로운 행동을 시키는 제안이 아닙니다.
**이미 하고 있는 일을 한자리에 모으는 제안**입니다.

그래서 이겨야 할 상대는 다른 부동산 앱이 아니라
**카카오톡, 엑셀, 메모장, 지도, 대출 계산기**입니다.

---

## 2. 어떻게 작동하나

둘의 조건을 각각 받아서, 매물마다 셋 중 하나로 답합니다.

```
나의 조건   ┐
            ├─→  매물 (최대 5개)  ─┬─→  둘 다 OK      → 그냥 둠
상대의 조건 ┘                      ├─→  한 명만 OK ★  → 누가 뭘 포기하는지
                                   └─→  둘 다 NO      → 뺌
```

**★ 이 한 줄이 전부입니다.** 나오는 건 점수가 아니라 문장입니다.

> "A로 가면 네 출퇴근이 왕복 36분 늘고 교통비가 월 4만원 더 든다.
> 대신 집값은 월 12만원 싸다."

왜 총점을 안 내는지 → [`decisions/0001`](../decisions/0001-no-total-score.md)

---

## 3. 핵심 설계 — 조건은 사람에 저장한다

**"이 집 몇 점"이 아니라 "나는 뭘 원한다"를 저장합니다.**

기존 앱은 매물마다 8개 항목을 채점합니다. 매물 5개면 40번입니다.
그리고 그 매물이 나가면 40번이 전부 날아갑니다.
상대에게 보낼 수 있는 것도 점수뿐이라 "왜 4점인데?"에 답을 못 합니다.

우리는 사람마다 한 번만 받습니다.

```
나   :  통근 40분 이내 · 반려동물 필수 · 예산 70만 · 출근지 강남역
상대 :  통근 30분 이내 · 방 2개 필수   · 예산 80만 · 출근지 여의도
```

| | 상대가 해야 하는 일 |
|---|---|
| 매물마다 채점 | 5개 × 8항목 = **40번** |
| 조건 한 번 입력 | **4번** |

40번을 요구하면 초대를 안 받습니다. 4번이면 받습니다.
→ [`decisions/0003`](../decisions/0003-conditions-belong-to-people.md)

## 4. 왜 이 방식인가 — 다른 안과 비교

| 안 | 어떤 방식 | 왜 안 하나 |
|---|---|---|
| 목록만 공유하고 각자 댓글 | 카톡이랑 똑같음 | 카톡을 두고 이걸 쓸 이유가 없음 |
| **조건을 각각 받아 대조** ★ | **선택** | |
| 상담원이 대신 골라줌 | 사람이 함 | 사람 수만큼 비용이 늚 |
| 주거비 계산기만 | 계산만 | 이미 다섯 군데가 무료로 함. 계산은 **가져다 쓰되** 단독으로는 안 함 |

### 주거비 계산은 가져다 씁니다

표시가격 말고 실제로 나가는 돈을 봅니다.

```
보증금에 묶이는 돈 + 대출 이자 + 월세 + 관리비 + 교통비 + 이사·중개비
```

**대신 계산에 쓴 가정을 화면에 다 밝힙니다.**

> 2026년 7월 기준 전세대출 평균 4.0%로 계산했습니다.
> 실제 금리는 심사 결과에 따라 다를 수 있습니다.

정직해서만이 아닙니다. 금리를 단정하면 금융 자문처럼 보일 소지가 있습니다.
가정을 밝히는 게 그 방어선이기도 합니다. → [`03-cost-model.md`](03-cost-model.md)

## 5. 사용자가 겪는 순서

| | 단계 | 내용 |
|---|---|---|
| 1 | 들어오는 지점 | 매물 3개째 저장할 때 "같이 볼 사람 있나요?" 한 줄. 처음부터 안 물어봄 |
| 2 | 초대 | 링크 하나. 가입 없이 열어보고, 조건 넣을 때만 로그인. **여기가 제일 중요** |
| 3 | 조건 입력 | 필수 3개, 출근지, 예산. 한꺼번에 안 묻고 필요할 때 하나씩 |
| 4 | 후보 모으기 | 최대 5개. 6개째 넣으려면 하나 빼야 함 |
| 5 | 충돌 보기 | 누가 뭘 포기하는지 + 주거비 차이 + 통근 차이 |
| 6 | 물어볼 것 | 관리비에 뭐가 포함되나, 전입신고 되나 같은 걸 질문 카드로 |
| 7 | 보러 갈 2곳 정하기 | **여기까지가 목표** |
| 8 | 다녀와서 | 유지 · 보류 · 제외. 빼면 자리가 비고 다음 매물이 들어옴 |

### 이런 경우엔

| 상황 | 어떻게 |
|---|---|
| 상대가 아직 안 들어옴 | 혼자서도 주거비랑 통근은 보임. **초대는 권유지 관문이 아님** |
| 매물이 사라짐 | '거래완료'로 표시하고 비교한 내용은 남김. 조건은 계속 살아 있음 |
| 조건이 하나도 안 겹침 | 추천하는 대신 "예산이랑 지역 중에 뭘 먼저 조정할까요"를 물음 |

## 6. 잘됐는지 어떻게 아나

찜이 늘어나는 건 성과가 아닙니다. 오히려 오래된 찜이 쌓이는 게 지금 문제입니다.

**먼저 보는 것**

| 뭘 보나 | 목표 |
|---|---|
| **초대 수락률** — 보낸 것 중에 상대가 조건까지 넣은 비율 | 재봐야 앎 · 최우선 |
| 둘 다 조건을 넣었나 | 재봐야 앎 |
| 보러 갈 2곳을 정했나 | 재봐야 앎 |

**나중에 보는 것**

| 뭘 보나 | 목표 |
|---|---|
| 중개사한테 연락한 비율 | 오르면 좋음 |
| 다녀와서 '제외'로 끝난 비율 — 헛걸음 지표 | 내려가면 좋음 |
| 한 달 넘게 방치된 찜 비율 | 내려가면 좋음 |
| 전월세대출 비교로 넘어간 비율 | 오르면 좋음 |

숫자가 비어 있는 건 지금 기준값이 없어서입니다. 지어내지 않았습니다.

## 7. 뭐가 잘못될 수 있나

| 위험 | 얼마나 | 미리 알 수 있는 신호 | 어떻게 |
|---|---|---|---|
| **상대가 안 들어온다** | **치명적** | 초대 수락률이 2주 만에 바닥 | 조건 없이 O/X만 찍는 형태로 줄여서 다시 측정 |
| 계산한 비용이 실제와 다르다 | 큼 | "이 숫자 뭐예요" 반응 | 숫자 옆에 가정을 항상 붙임. 단정 안 함 |
| 매물이 너무 빨리 사라진다 | 중간 | 후보 중 거래완료 급증 | 조건을 사람에 저장해서 다음 매물에 재사용 |
| 충돌 화면이 싸움을 키운다 | 중간 | 그 화면 이후 이탈 증가 | 이기고 지는 표현 안 씀. 주고받는 문장으로만 |
| 상대에게 예산·직장이 노출된다 | 중간 | 조건 입력하다 나감 | 항목별로 공개 범위 선택. 충족 여부만 보이고 숫자는 숨기는 옵션 |

## 8. 만드는 순서

**1번이 안 되면 나머지는 만들 이유가 없습니다.**

**1 · 초대를 받는지 먼저 재기**
목록 공유 링크 + 상대가 O/X만 찍는 화면.
끝난 걸로 치는 기준: 보냄 → 열어봄 → 수락 → 첫 반응이 각각 기록되고 2주치 숫자가 나온다.

**2 · 조건을 사람에 저장하는 구조**
어떤 항목을 받을지 정하고, 출근지·예산을 어느 화면에서 받을지 정한다.
끝난 걸로 치는 기준: **매물을 전부 지워도 조건이 남아 있다.**

**3 · 주거비 계산기**
6개 항목 계산식 + 각 가정의 출처 문구.
끝난 걸로 치는 기준: 모든 숫자 옆에 가정이 붙어 있고, 단정하는 문장이 없다.

**4 · 충돌 화면**
셋으로 갈리고, 가운데는 문장으로 나온다.
끝난 걸로 치는 기준: **점수 UI가 어디에도 없다.**

**5 · 질문 카드 + 보러 갈 2곳 확정**
유지·보류·제외로 자리가 도는 것까지.

## 아직 모르는 것

숫자가 비어 있는 항목은 지어내지 않고 그대로 뒀습니다.

**이 제안이 기대고 있는 건 하나입니다 — 두 번째 사람이 실제로 들어온다는 것.**
나머지는 설계로 줄이거나 재보면 되는데, 이것만은 만들어봐야 압니다.
